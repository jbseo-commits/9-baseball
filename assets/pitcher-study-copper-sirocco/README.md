# 코퍼 시로코 — 투수 아트 후보

29세 성인 여성 우완 투수. 구릿빛 땋은 포니테일, 따뜻한 피부와 주근깨, 차콜·코퍼 크롭 저지와 스포츠 쇼츠가 특징이다. 기존 16명 로스터·study slug와 겹치지 않는 새 오리지널 디자인이다. 등급·HP·대사·밸런스는 지정하지 않았다.

**상태: 아트 후보 / reference_unverified / held_pose_candidate.** 게임 로스터·렌더러·공 출발점에는 연결하지 않았다. 120프레임 파일 규격과 매끈한 120개 관절 그림은 서로 다르다.

## 검토 파일

- `source/copper-sirocco-portrait.png`: 1024×1536 투명 전신 원화. 원화 수정 이전 출력은 `source/originals/`에 보존.
- `source/copper-sirocco-keys.png`, `source/copper-sirocco-bridges.png`: 각 1536×1024, 3×2 시트. 일부 전신은 명목 셀 경계를 넘어가므로 공용 빌더의 연결된 알파 실루엣 추출을 사용한다.
- `source/poses/`: 원화 해상도 개별 포즈 12개.
- `poses256/`: 동일 축소율로 패킹한 투명 포즈 12개.
- `atlases/copper-sirocco-pitch-120-atlas.png`: 256×256 셀, 10×12, 120프레임, 60fps, 2초. 릴리스는 76프레임(0부터 시작).
- `previews/`: 포즈 모음·축소 비교·재생 프리뷰. 실제 게임 화면 캡처가 아니라 에셋 검토용이다.
- `copper-sirocco-manifest.json`, `validation.json`: 타임라인·실제 검사·미검증.
- `references.json`: 새 영상 후보, 정규화 키, 검색 시각·질의, 재생 차단, 빈 관찰 타임스탬프.
- `PROMPTS.json`: 내장 image_gen에 실제 전달한 원화·수정·키포즈·연결포즈 프롬프트.

빌드: `python scripts/build-copper-sirocco.py` (Pillow·NumPy, MP4 생성은 ffmpeg/ffprobe 필요). [빌더](../../scripts/build-copper-sirocco.py)는 공용 추출 계약을 재사용하며 다른 투수의 스크립트를 바꾸지 않는다.

## 참고영상과 관찰 한계

이번에 새로 검색·예약한 포수 뒤 시점은 [Gerrit Cole 불펜 게시물](https://x.com/BryanHoch/status/2028857346869375058), 심판캠은 [Padres–Dodgers NLDS Game 1](https://www.mlb.com/video/best-of-ump-cam-in-game-1-of-the-padres-dodgers-nlds)이다. 기존 과거 출처 다섯 URL과 다르다. 두 후보는 이번 실행 사용 이력에 예약하여 다음 실행에서 재사용하지 않는다.

자동 승인 검토가 researcher의 공개 MLB 페이지 GET을 작업 범위 밖이라고 거부했다. 우회하지 않았다. 대체 페이지는 검색에서 발견했으나 재생 시도는 하지 못했다. **실제 영상 재생·관절 프레임 분석·키포즈 타임스탬프 관찰은 없다.** 포즈는 일반 투구 메커니즘을 바탕으로 직접 설계한 후보 그림이다. 해당 영상에서 동작을 추출하거나 검증했다고 주장하지 않는다.

## 동작 계약과 남은 검수

오른손에 공, 왼손에 글러브. 준비·코일·왼무릎 상승·디딤·팔 가속·릴리스·팔로스루·회복을 각각 다른 실루엣으로 그렸다. 릴리스 키포즈는 공이 분리된 직후의 빈 오른손이며 이후 셀에는 공이 없다. 공 비행은 별도 런타임 에셋이므로 이 후보에 그리지 않았다.

12개의 그려진 포즈를 시간에 따라 유지하는 패킹이다. 전체 이미지 회전·이동으로 고유 프레임 수를 늘리지 않았다. 자세 전환에는 점프가 남으며, 자동 사지 트윈·완성 60fps 애니메이션이라고 표시하지 않는다. 더 많은 직접 그린 중간 포즈와 실제 영상 관찰이 필요하다.

`landmarks.json`의 발·몸 중심·공 위치 표시는 후보 PNG의 대략적인 수동 관찰 좌표다. 가려진 공은 null로 기록했다. 원영상에서 측정한 좌표가 아니다. 전신 알파 하단을 맞춘 패킹은 런타임 마운드의 축발 고정을 입증하지 않는다. 축소 검토는 128/192/256px 비교이며 실제 모바일 세로·가로·PC 게임 장면에서 접지·원근·UI 겹침 검수와 블라인드 품질 평가는 아직 미실행이다. 최종 상업 아트 품질 통과로 표시하지 않는다.

## 구현 전 영향도 분석

| 축 | 판단 | 범위·대응 |
| --- | --- | --- |
| UI·레이아웃 | 영향 없음 | src·CSS·로스터·도감 변경 없음 |
| 입력·제스처 | 영향 없음 | 이벤트 변경 없음 |
| 게임 로직·밸런스 | 영향 없음 | 투구 결과·HP·카드 변경 없음 |
| 저장·불러오기 | 영향 없음 | save schema·투수 ID 등록 변경 없음 |
| 모바일 뷰포트 | 확인 필요 | 축소 후보 비교. 실제 게임 화면 검수는 연결 전 필요 |
| 스크롤·오버플로 | 영향 없음 | 전역 및 화면 CSS 변경 없음 |
| 기존 사용자 플로우 | 영향 없음 | 타이틀→경로→전투 등에서 후보 미사용 |
| 테스트·회귀 | 영향 있음 | 후보 전용 빌드, 실제 알파·치수·파일 개수·프레임·재생 길이 검사 |
| 빌드·배포 | 영향 있음 | 독립 Python 빌더·미사용 art 폴더만 추가. Vite import·public 미변경, 배포 안 함 |

게임 전체 테스트·smoke·production build·배포 후 검수는 이 미연결 아트 후보 작업에서 실행하지 않았다. 실제 실행한 범위만 `validation.json`에 기록한다. 게임 연결을 승인받아 진행할 때 기존 회귀 계약을 적용한다.
