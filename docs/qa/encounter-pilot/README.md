# 투수 기믹 4명 시범 전투 검증

검증일: 2026-10-31. 기준 main: `b29fb6a`. 작업 브랜치: `codex/pitcher-encounter-pilot`.

20명 설계 중 첫 4명의 전투 규칙을 구현했다. 새 20명 모션 후보는 반입하지 않고 main의 기존 아트를 사용했다. 이 결과는 작동·회귀 근거이며 사람의 재미나 상업 품질, 최종 밸런스를 입증하지 않는다.

## 적용 범위

- 레드: 첫 두 공 한곳 → 다음 두 공 두 후보 → 같은 열 세 후보.
- 청록: 실제 소비한 투구 기준 바깥 열 → 바깥 열 → 가운데 열 반복. 준비·카드 배치·취소는 패턴을 진행시키지 않는다.
- 코발트: 초반 안쪽 세 존, 2스트라이크부터 여섯 존. HP가 낮아져도 준비 예산은 기본 2를 유지한다.
- 타이런트: 낮은 세 존의 비정확 안타 HP 압박 ×0.75. HP 60% 이하에서 가운데 존까지 벽 확장. 정확 안타로 깨면 **다음 두 투구**에 해당 벽 영역 안타 HP 압박 ×1.25. 안타와 진루를 무효화하지 않는다. 무료 기본 스윙으로도 벽 해제가 가능하다.

실제 Duel/PlayableRun 판정과 기존 카드·에너지·상대 등급을 사용한다. URL의 명시적 `encounterPilot` 및 버전 1 태그로만 활성화한다. 기존 저장의 artId로 소급 적용하지 않는다. 각 투수/시드는 독립 sessionStorage를 사용하고 본게임 런 localStorage를 읽거나 쓰거나 삭제하지 않는다.

공개 예고·스카우팅·확률·피해 예측은 최종 착지 분포를 공유한다. 기존 trick 투수의 실제 RNG/착지 샘플링 경로는 유지하면서, 표시 분포와 예측의 중복 변환을 수정했다. 따라서 다른 16명의 실제 기믹은 유지되지만 기존 trick 공개 표시에는 이 수정이 적용된다.

### 실제 시범 전투 완주

브라우저 탭 입력만 사용하고 매 행동·다음 공 상태를 실제 엔진과 비교했다. 카드·HP·아웃·결과를 주입하지 않았다. 정책은 공개 예측 구간만 읽으며 숨은 pending 착지를 보고 선택하지 않는다.

| 상대 | 시드 | 결과 | 투구 | 남은 HP | 아웃 |
|---|---:|---|---:|---:|---:|
| 레드 | 3 | 강판 → 보상 | 4 | 0 | 0 |
| 청록 | 3 | 강판 → 보상 | 5 | 0 | 0 |
| 코발트 | 3 | 강판 → 보상 | 6 | 0 | 0 |
| 타이런트 | 3 | 패배 | 18 | 10 | 3 |
| 타이런트 | 7 | 강판 → 보상 | 19 | 0 | 2 |

타이런트의 빈틈 2공 상태에서 재로드해 pending·남은 빈틈·전체 상태 일치를 확인했다. 모든 보상/패배 상태의 재개와 본게임 저장 미접근, 브라우저 오류 0을 확인했다. 자동 정책이 모든 시드에서 이기지는 않는다. 보스 난도·설명 이해도는 사람의 후속 플레이가 필요하다.

독립 코드 검수는 최종 GO: 첫 투구 스냅샷, 패턴 카운터, 타석 변경, 구종 후보 메타데이터, 저장/공개 정보 경계와 허위 구종 확장 메시지를 확인했다. 검수자가 위 브라우저 플레이를 직접 관찰한 것은 아니다.

```bash
pnpm exec vitest run --maxWorkers=4
```
