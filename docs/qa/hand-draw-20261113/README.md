# 실제 손패 자동 공개와 순차 드로우

2026-11-13 KST. 매 타석 오른쪽 손패 열기를 반복해야 한다는 피드백을 해결하는 기능 프리뷰다. 기존 Draft PR121에 이어서 작업하며 main은 변경하지 않는다.

새 타석/다음 공의 실제 deciding 진입에 손패를 자동으로 펼친다. 카드는 기존 실제 슬롯에 위에서 차례로 내려와 정착하며, 새로 뽑은 인스턴스에만 `뽑음` 표시가 남는다. 새 카드 위치로 한 번 스크롤한다. 바로 선택·드래그·스택할 수 있으며 확인창이나 닫기 단계는 없다. 수동 닫기 이후 aim·선택·단순 재렌더만으로 다시 열지 않는다. 다음 실제 진입/드로우가 있어야 자동으로 연다. 배치 후 접기와 결과에서의 수동 복기·자동 진행은 유지한다.

엔진 `draw()`에서 실제 push한 카드 인스턴스 ID 순서만 WeakMap 영수증으로 기록한다. 상태 필드·직렬화·RNG·드로우 수·순서·비용·피해는 바꾸지 않는다. 소비 직후 같은 ID가 재순환되어도 차집합 추측 없이 잡는다. 영수증은 flight/committing에서 읽지 않는다. 결과에서 생긴 드로우는 다음 deciding까지 누적하며, 다음 공의 영수증으로 덮어쓰지 않는다. 이미 저장된 손패를 로드하면 자동 공개/입장 동작만 하고 NEW나 새 드로우 소리를 조작하지 않는다.

기존 카드의 React key·선택 상태·카메라·9존 좌표는 그대로다. 수직 이동은 별도 WAAPI `translate`로 기존 회전·선택 transform과 분리한다. 착지는 실제 애니메이션 완료에 연결하며, 같은 ID/배치에는 한 번만 효과음이 난다. 음소거·숨김·중단·100ms 이상 늦은 완료는 재생하지 않는다. 클립 영역에 45% 미만 보이는 카드는 소리만 나지 않는다. reduced-motion에서는 즉시 표시하고 이 연속 착지음을 생략한다.

작은 가로 화면에서 3장은 오른쪽 그림/왼쪽 텍스트를 유지한 짧은 카드로, 4장 이상은 두 열로 공개한다. 이름·비용·효과를 우선하며 좁은 2열에서는 큰 원화와 범위 그림을 접는다. 상세/선택과 실제 범위·판정은 기존 값을 그대로 쓴다. 비교용 과거 `battleFixture` 화면은 수동 손패 계약을 유지하고 실제 게임 경로에서 자동 공개를 검증했다.

## 공개 확인에서 잡은 단일 카드 스크롤 회귀

첫 게시 d8200cf의 공개 JS/CSS 지문은 일치했고 작은 화면3장 드로우도 통과했지만, 844×390 한 장 추가에서 새 카드가 위로 밀렸다. 브라우저의 scroll-snap/overflow-anchor가 낙하 translate를 따라 스크롤을 재보정했다. [실패 화면](history/single-card-scroll-drift-d8200cf.png)과 [실패 로그](history/public-d8200cf-failure.txt)를 보존한다.

드로우 중인 손패 행에만 `scroll-snap-type:none;overflow-anchor:none`를 적용했다. 카드 그림·배치·연출 후보를 추가한 것이 아닌 별도 기능 회귀 보정이며 시각3/3·NOT_IMPROVED를 초기화하지 않는다. 수동 닫기/다음 단계에서 기존 배치가 끝나면 원래 스크롤 규칙으로 돌아간다.

`node scripts/qa-hand-draw.mjs`가 실제 엔진/입력으로 재현하는 회귀 검사다. `BASE_URL`, `QA_OUT`, `PLAYWRIGHT_MODULE`, `CHROMIUM_PATH` 환경값을 받는다. 기본3장 시나리오는 reshuffle 카드1장 손패·나머지 더미로 구성한 QA 초기조건이며 자연 첫5장 흐름과 구분한다.

[최종8사례](scroll-regression.json)에서 단일 추가카드(568/667/844) 전체 가시율100%·소리1회, 3장(0.5/1/2배속과 넓은 화면) 각 이름/비용/효과 가시율100%·소리3회, reduced 소리0을 확인했다. 실제IDs·엔진저장·본편저장 보존과 오류0도 통과했다. 넓은 화면의 장식 프레임90.6%가 보이는 기존 경우를 임의로 실패/통과하지 않고, 단일카드 전체≥95% 기준은 유지하면서 모든 새 카드의 이름·비용·효과 각각을 행·버튼·뷰포트 교집합과≥95%로 검사했다. 별도 reviewer가 이 목적별 정밀화가 기준 완화가 아님을 확인했으며 [처음 과도하게 넓힌 프레임 기준 실패](history/overbroad-frame-criterion.txt)도 보존한다.
