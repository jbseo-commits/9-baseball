## Design decision

The prior reactive prototype needed a swing launch 140ms into a 300ms flight (160ms preparation), before the slider's late break at ~225ms. Slower flight would change the interaction and demand new balance. This cycle instead tests the existing card game's decision loop: unlimited time to choose cards/aim/supports, confirm once, watch the authoritative result, read it without automatic advancement, and restart the same seed to try another player-authored choice.

This is a real first opponent generated by `createV10Duel(20261118)` and entered through the normal reachable node, with actual dealt cards, energy, current encounters and roster. No grants, damage formula, synthetic swipe judge, save reads/writes, or live game rule changes. Preparation/take/supports use the existing engine. Completion stops at the first opponent's terminal state; rewards/map/deckbuilding are not part of the lab. Same-seed replay is one conditional sample, not expected value or proof of an optimal strategy.

The inherited preview's outcome-dependent pre-impact timing was unsuitable for this experiment. The lab now uses the actual roster release plus a constant 300ms flight, with equal pre-impact actor/ball samples across hidden outcomes. Result-specific feedback and knockout hold start after impact. Reduced-motion remains the existing 60ms presentation; preparation does not pitch. Production presentation remains unchanged.

PXF assets/license/source in #123/#124 remain untouched. This independent main-based experiment imports no new FX or external assets. The approved ×3/×1.5/×1 swipe values remain earlier prototype hypotheses, not current engine rules. No card/pitch synergy or pitch-specific damage mapping has been invented.

## Limits and next experiment

No human comprehension/fun study, physical touch hardware, latency/performance validation, or commercial/art-quality acceptance. Fixed one-seed first opponent cannot establish deck diversity, repeatability across encounters, or pitch identity. The next useful experiment is a contextual instruction inside the existing hand/decision UI (without a permanent banner), followed by people trying two choices and explaining the outcome. Keep alternate-outcome counterfactuals and new reaction rules deferred.
