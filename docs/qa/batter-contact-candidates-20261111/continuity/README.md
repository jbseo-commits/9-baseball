## 빈 프레임과 수정 후보의 구분

후보2 실제 녹화에서 처음 AVIF→WEBP로 바뀌는 순간 타자가 사라지는 프레임을 관찰했습니다. 원본 셀은 비어 있지 않고 DOM 배우는 visible/opacity1 상태였습니다. 디코드/첫 페인트/리소스 전환과 강하게 연관되지만 캡처 영향까지 완전히 분리한 원인 입증은 아닙니다.

후보3은 두 아틀라스를 고정된 레이어로 유지하고 진입 시 미리 디코드합니다. 한 투구가 시작될 때 준비가 안 됐거나 실패했다면 그 투구 전체는 기존 렌더러를 유지합니다. 도중에 모드를 바꾸거나 호스트 시계를 재시작하거나 입력 단계를 추가하지 않습니다. 실제 활성 컨텍스트가 없는 fallback에는 새 CSS도 적용하지 않도록 격리했습니다. 착탄 코스는 실제 result·호스트 접촉 구간 이후에만 얇은 그리드·실제 셀·문구로 확인합니다. 이 코드도 **미공개 참고 후보**입니다. 기술적 빈 프레임 수정이 성공하더라도 블라인드 품질 실패를 뒤집지 않습니다.

`candidate2-preserved/`와 `candidate3-preserved/`는 실행 불가한 `.txt` 코드·검사 원문입니다. live `src`/`assets`로 연결하지 않습니다. 프롬프트의 로컬 경로는 당시 입력의 이력이며 원본과 정규화 셀은 함께 보존했습니다. 기존14개 그림·나머지 PRE/접촉/POST의 출처는 [앞선 아카이브](../extension/README.md)입니다.

존 밖 자동 헛스윙 추정, 외부 파울의 미등록 접촉, 느린 영상 창의 한계는 [QA 정정 기록](QA-FIXTURE-CORRECTION.md)을 함께 읽어야 합니다.
