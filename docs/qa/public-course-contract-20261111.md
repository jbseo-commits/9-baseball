# Public course-presentation foundation

This change prepares course playback data without enabling roulette lights, new batter art, ball destinations, audio, haptics, or input phases. The renderer does not consume `playback.course`. The local visual candidate failed the independent improvement gate and remains separate in Draft #115.

`captureExecution` freezes the player's already displayed live zones, earned clues, face labels and node/pitch counter. The face strings determine visual weights. Exact hidden probabilities, pending zone, seed and engine rolls never enter this public plan. The stored intent repertoire is used because it is the grid the player actually sees; recomputing a repertoire can disagree with that frozen surface. This mismatch is covered by a failing-then-fixed regression.

The visual order uses a separate deterministic local generator. It never consumes game RNG. An impossible zone is excluded only when the displayed repertoire or earned clue establishes that exclusion. A displayed0% may be a rounded small positive probability, so it retains a floor weight. At READ0/1, differing exact distributions with identical public faces produce the same snapshot. Hidden-zero cadence cannot be used as a scouting side channel.

The existing accepted-result save barrier is authoritative. The host attaches the contract only for a saved live V10 pitch, after successful durable storage, with matching node and pitch counter. Preparation, memory previews, non-durable actions and the actual60ms reduced-motion path do not attach it. Reduced motion retains the original immediate result timing. Reload does not construct a second course playback or resample a result.

The accepted destination is read lazily once, when a future consumer first calls the getter at or after public LOCK. The pure frame function never calls it before LOCK. Formal hit/HP/result timing is unchanged. The host also retains the player's own committed aim for future outside-swing presentation. The existing presentation epoch remains the clock; this change adds no timer or rendering RAF.

The nine-zone plane remains an **unapproved authoring diagnostic**, including its explicit outside-side proposal. The incoming-flight helper holds the target if a callback is late; it is unused by the live renderer. Mathematics alone does not establish a physical plane, complete outgoing contact/pass trajectories, continuous animation, sound, touch UX or commercial quality. Future consumers must prove DOM/image/ARIA/audio privacy, save failure/reload behavior and motion quality before enabling it.

Impact analysis: UI/layout, input, probability/balance, save schema, viewport, scroll and screen flows remain unchanged; the only host additions are transient public execution metadata and an unused playback field. No global styles, engine mutation, packages or services change. Risks are accidental private-probability weighting, mismatched displayed eligibility, an early target read, or future consumers skipping the save/LOCK gate. Tests cover those boundaries. Build review must verify the held art is absent, rather than relying on a DEV visual switch to omit static imports.

Validation: eleven pure-contract tests include20 actual registered release origins ×10 targets ×6 rates (1200 incoming-flight combinations); ten public-host tests cover displayed eligibility, READ privacy, rounded0%, preparation exclusion, durable save, one-read target, public aim and the actual reduced-motion timeline. Existing snapshot/save-barrier tests remain mandatory. These are automated contract checks, not evidence of game feel or a completed roulette feature.
