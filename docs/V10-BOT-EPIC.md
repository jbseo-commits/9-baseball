# V10 데미지 인식 전투 봇 epic — 설계안

> 상태: 설계안 (미구현). 승인 후 E1부터 한 바퀴씩.
> 배경: 1000회(200시드×5변형) 고정 봇 측정 — 전 변형 평균 3.2노드 lost,
> 승 2건, support 변형 후퇴(2.8노드). 강화·유물 상대가치(INBOX 7)는
> 봇이 1막 보스를 넘는 빈도가 나와야 잴 수 있다.

## 1. 목표

- 동일 시드에서 현행 봇(base)보다 **노드 도달·투수 강판률**이 높은 전투 봇.
- INBOX 7에 답할 측정 하네스의 구동기: 변형별 완주율 차이가 재현되게 나온다.
- 산출물: `policy.js` 신규 함수 + 드라이버·리포트 확장. **엔진·UI·저장 변경 0.**

## 2. 비목표

- 인간 플레이 가이드·밸런스 조정. 봇 수치는 봇 행동 차이일 뿐
  인간 재미·밸런스 증거가 아니다 (zone-report식 scope 면책을 전 산출물에 유지).
- 공유 `planAction`의 시그니처·레거시 동작 변경. 기존 600+ 테스트 불변.
- "마스터피스" 선언. 품질은 올리되 주장은 올리지 않는다.

## 3. 현행 봇의 한계 (측정 근거)

1. 가치 함수가 **기대 루타 중심** (`policy.js:36-44`): 투수 HP를 직접 안 본다.
   개막전(HP 72)에 중앙값 38 피해로 20% 탈락.
2. **지원 미사용**: 무작정 부착은 불법 지원 스톨(5분 실측), problem 검사 부착은
   피해 분담(80%)으로 후퇴. CONNECT·피해율 인식 선택이 없다.
3. **준비(preparation)·지켜보기 규율**이 레거시 휴리스틱 그대로
   (`policy.js:20-24`): V10 덱(정찰/관찰 카드 비중)과 따로 논다.
4. 유물 상호작용 미반영: `v10RelicDamagePlan`을 읽지 않는다.

## 4. 설계

### E0. 평가 함수 `evaluateV10Action(s, action)` (신규, policy.js)

- 입력: 합법 액션 하나 (take / card+supports, aimZone 포함).
- 출력: 기대 투수 피해 `{expectedDamage, pitches: 1}`.
- 계산: `previewV10Stack`의 hit/foul/whiff/out 확률 ×
  `damageForOutcome`(`pitcher-hp.js:40`) × `stackPlan.damageRate` ×
  유물 배율(`v10RelicDamagePlan`, 읽기만).
- 엔진 공식 복제 금지(C6): 확률은 preview, 피해표는 damageForOutcome,
  배율은 relicPlan — 모두 **호출해서 읽기**만 한다.

### E1. 단일 카드 선택 교체 (드라이버側)

- 매 타석: 합법 손패 × 9존 × {take} 중 `evaluateV10Action` 최대 선택.
- take는 피해 0 + 아웃/볼카운트 전이로 평가 (헛스윙 삼진 회피 가치 포함).
- 완료조건: 단위테스트(합법성·결정성) + 전투 주행 3시드 종료.

### E2. 지원 선택 (E1 위)

- 후보: 합법 손패 중 1~2장 × aimZone(메인과 같은 존 + 인접 존).
- `previewV10Stack(...).problem` 있는 조합은 탈락 (11바퀴 스톨 교훈).
- 선택 기준: E0 기대 피해 − 카드 소모 기회비용(남은 아웃·투수 잔여 HP로 가중).
- 완료조건: support 변형이 base 대비 노드·강판률 상회 (동일 시드).

### E3. 준비·유물 규율

- 준비 카드 2회 사용 조건을 E0 이득으로 판단 (현행 고정 순서 대신).
- 유물 보유 시 relicPlan 배율을 E0에 반영 (이미 읽기만 하므로 추가 작업은 작음).
- 완료조건: 유물 보유런/미보유런 분리 측정 가능.

### E4. 풀런 통합 + 1000런 재측정

- 드라이버·리포트에 신봇 탑재 (`--bot=base|damage` 플래그).
- 완료조건: 1000회 전 종료·무예외 + base 대비 개선 수치 기록.

### E5. INBOX 7 답변

- 변형(강화 7종·유물 3종 1종씩) × 신봇 완주율 표.
- scout+ 가설 판정: 가설 유지/기각을 수치와 함께 기록 (단정 금지, 재현 시드 명시).

## 5. 전역 제약 (매 바퀴 적용)

- C1~C7 준수. `zone-report 30` 불변. 전체 테스트 + build.
- 한 바퀴 = E* 안의 한 줄. red-first, 로컬 커밋, push·배포 금지.
- 브라우저 캡처는 playwright 부재로 미검증 표기 (로직-only).

## 6. 열린 질문 (구현 전 결정 필요 없음, 기록용)

- 기대 피해만으로 충분한가, 아웃 회피(타석 연장) 가중치는 얼마가 적정한가.
- 유물별(ledger/scope/radar) 평가 가중을 따로 둘 것인가.
- 봇이 인간 전략을 대표하지 못한다는 한계를 문서 어디까지 명시할 것인가.
