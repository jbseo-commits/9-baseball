# MAIN RUN 카드 에너지

사용자 요청: 카드 자원을 소비하는 슬더스식 전투. 기준은 `origin/main`의 `efff947`. 이번 변경은 카드 에너지와 비용을 연결하며 세계관, 투구 확률, HP 피해 공식, 런 구조를 바꾸지 않는다. 참고 GitHub 주소는 아직 확인되지 않았으며 외부 코드·이미지를 가져오지 않는다.

## 구현 규칙

- MAIN RUN(V10)의 한 공을 한 턴으로 보고 에너지 3으로 시작한다. 다음 공·다음 타자·새 전투를 실제로 시작하면 3으로 충전한다. 결과 화면이나 저장 복원은 충전하지 않는다.
- 준비 카드는 실행할 때 비용을 내고 공을 진행하지 않는다. 메인 공격 카드와 지원 카드는 스윙 실행 때 합산 비용을 낸다. 선택, 취소, 존·순서 편집은 무료다.
- 151종 카드에 비용을 명시한다. 기본 1, 표의 무거운 카드 2, 기본 집중 준비 `setup` 0. 강화와 지원 역할은 원래 카드의 비용을 유지한다. 카드 도감, 제안 화면, 손패, 미리보기, 실행은 같은 `cardCost`를 쓴다.
- 준비는 기존 타석당 최대 횟수를 유지한다. 지원 카드는 기존처럼 추가 커버만 제공하며 메인 효과·조건을 실행하지 않는다. BASIC SWING과 지켜보기는 무료라 에너지 0에서도 진행할 수 있다.
- 에너지가 모자라거나 스택이 잘못되면 카드, RNG, 투구, 통계, 에너지를 바꾸지 않는다.
- V9 튜토리얼은 기존 규칙을 유지한다. V10 저장 키는 유지하고 선택적 `battle.energy`를 추가한다. 값 0은 보존하고 누락된 예전 저장은 현재 공의 에너지 3으로 한 번 초기화한다. 값이 있으면 정수 0~3인지 검사한다.

## 검증 기록

구현 전 상태. 기존 main의 전체 테스트는 887개 통과·5개 실패이며 VFX 값, CSS 선택자 문자열, 마지막 CSS import 가정 관련이다. 이 5건은 이번 자원 작업과 구분한다. 독립 검토는 공마다 충전, 비용 단일 함수, 실행 실패 불변성, 지원 조건 보존과 저장 호환을 우선하도록 권고했다. 실제 검증 결과는 구현 후 기록한다.

## 구현 후 검증 기록

- 핵심 에너지·스택·가이드·실제 App long-press 경로: 5개 파일 / 27개 테스트 통과.
- 전체 `pnpm test`: 150개 파일 / 900개 테스트 중 145개 파일, 895개 통과. 실패 5개는 구현 전 기준선과 같은 항목이다: `ball-exit-vfx` trail cap 20 대 실제 22, `cinematic-director-css` 및 `cinematic-live-bridge` 선택자 문자열 가정, `title-pixel` 및 `v12-ux2-polish`의 title-pixel 마지막 import 가정.
- `pnpm build` 통과(1090 modules); `pnpm check:dist` 통과(49.4MB / 50MB). 기존 500KB 초과 chunk 경고는 남아 있다.
- 거부 전 상태를 복사해 RNG·손패·통계·에너지 불변성을 검사하고 준비 검증을 실제 5장 손패로 보강했다. 변경된 에너지 테스트 2개 파일 / 8개 테스트를 다시 실행해 통과했다.
- `node scripts/zone-report.js 10` 종료 코드 0. 이 보고서는 기존 첫 투수의 공개 정보 기준이며 에너지 밸런스나 사람의 재미를 입증하지 않는다. `v10-report.js 10`은 지도 10/10 유효, 보스 경로 30/30을 확인했다. 구 보고서의 `committedActs`는 13/30으로 관찰됐으며 해당 지도·보고서·HP 코드는 기준 main과 동일하다. 이 과거 갈림길 지표를 에너지 합격 기준으로 사용하지 않았다.
- 실제 Chromium 검증: 375×667·412×743·390×844에서 비용·잔량 표시, 선택/취소 무소비, 준비→두 장 스택 차감, 잔량 0의 저장 복원, 무료 준비/지켜보기, 다음 공과 타자 충전, 타석 준비 횟수 보존을 확인했다. 1440×900의 PC 세로 iframe, 터치 가로 회전→세로 복귀, 새 게임→카드 설명→전투→보상→지도→시설 이동까지 16/16 체크 통과. 고정 시드와 명시한 저장 fixture를 사용했으며 사람 플레이 자료가 아니다.
- 기존 `qa-shots.mjs`의 412×743·375×667 경로·전투·결과·보상 검사는 18/18 통과했다. 화면 산출물은 로컬 `work/card-energy-qa/`에 있으며 GitHub에 업로드한 프리뷰가 아니다.
- 좁은 모바일 전투 HUD는 첫 측정에서 넘쳤고, 이후 에너지 정보를 실행 행으로 옮겼다. 실행 버튼의 하단 잘림도 발견되어 V10 에너지 화면에만 portrait 실행 행을 30px 늘렸다. 최종 실제 측정에서 에너지 줄, 상단 제어, 두 실행 버튼 모두 화면 안에 들어오고 문서 가로/세로 넘침이 없음을 확인했다. 경기장 유동 영역이 추가 높이를 흡수하며 카드 높이와 터치 영역은 유지한다.
- 작은 375×667 휴대폰에서 전투→보상→지도→시설을 추가 검증해 2/2 체크를 통과했다. 실제 경로 스크롤 소유자는 문서이며 높이 832px, 뷰포트 667px에서 `scrollTop` 165px까지 이동했다.
- 같은 독립 검토자가 계획·최종 diff·테스트 로그·QA JSON과 375px 이미지를 직접 확인해 PASS를 판정했다. 새 MAIN RUN 전환 후 긴 누르기에서 비용 설명이 누락되는 effect 의존성 문제와 실행 불가 이유의 우선순위를 수정하고 행동 회귀로 확인했다. 원격 SHA는 작업 보고에서 확인한다.
- 공개 main 배포는 수행하지 않았다. 현재 GitHub PR 목록은 검증 가능한 목록을 얻지 못해 충돌 여부를 미확인으로 남겼다. 참고 자료의 저장소 주소는 아직 확인되지 않았다.
