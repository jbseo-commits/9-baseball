# 투수 기믹 시범 전투: 범위와 영향도

사용자의 20명 기믹 설계 승인 후, 제안한 첫 구현 단위인 레드·청록·코발트·타이런트 네 명을 적용한다. 기준은 main `b29fb6a`, 작업 브랜치는 `codex/pitcher-encounter-pilot`이다. 신규 20명 모션 후보는 별도 검수 대상이며 이 변경에 반입하지 않는다.

## 구현 전 정한 범위

- 명시적 버전 1 태그와 URL 선택으로만 네 기믹을 활성화한다. artId만으로 기존 저장에 소급 적용하지 않는다.
- 레드의 기존 튜토리얼 보장, 청록의 소비 투구 주기, 코발트의 2스트라이크 확장·기본 준비 예산, 타이런트의 정확 안타·다음 두 투구 빈틈을 구현한다.
- 기존 Duel/PlayableRun과 실제 판정을 재사용한다. 별도 전투 엔진이나 검증용 카드·HP·승리 주입을 만들지 않는다.
- 최종 착지 분포를 공개 그리드·정보·스카우팅·예측이 공유한다. 기존 trick 실제 샘플링과 RNG 순서는 보존하고 예측의 중복 변환을 제거한다.
- sessionStorage를 시범전투별로 분리한다. 본게임 localStorage 런을 읽거나 쓰거나 삭제하지 않는다.
- 한 줄 의도와 벽/빈틈 존 표시만 추가한다. 중앙 존, 손패, 에너지, 기존 조작 위치를 유지한다.

## 구현 전 9축 영향도

| 축 | 판단 | 대응·검증 |
|---|---|---|
| UI/레이아웃 | 영향 있음 | 의도 한 줄 및 존 표시만 추가. 전역 HUD 변경 없이 작은 가로 화면 확인 |
| 입력/제스처 | 영향 있음 | 준비·미리보기·배치·취소로 패턴이 진행되지 않게 분리. 기존 탭과 카드 스택 실제 조작 |
| 규칙/밸런스 | 영향 있음 | 실제·예측 HP 계산 공유. 안타 보장과 기본/지켜보기 유지. 새 규칙을 명시적 버전으로 격리 |
| 저장/불러오기 | 영향 있음 | 버전·상대·현재 투구 스냅샷 검증. 기존 저장 보존. 빈틈 중 재로드 일치 확인 |
| 모바일 뷰포트 | 영향 있음 | 가로 우선. 667×375부터 PC까지 확인하고 세로 회전은 회귀 검사 |
| 스크롤/오버플로 | 영향 낮음 | html/body override 추가 없음. 지도 스크롤 및 비전투 화면 확인 |
| 기존 사용자 흐름 | 영향 있음 | 전투→HP 0→보상, 일반 런 지도·다음 노드·타이틀 이어하기 확인 |
| 테스트 | 영향 있음 | 소비 투구/정확 판정/빈틈/세이브/예측 일치 회귀 추가. 전체 테스트와 smoke 실행 |
| 빌드/배포 | 영향 있음 | 하위 경로 production build와 dist budget. main을 병합하지 않고 기존 Pages 브랜치 프리뷰 사용 |

## 독립 구현 전 검토

GO 조건: 기존 swing-preview의 trick 변환을 중복 적용하지 않을 것, artId 대신 명시적 버전을 사용할 것, 나머지 상대의 실제 기믹을 유지할 것, 저장 검증과 map/opponent 복사본을 함께 다룰 것, 기존 PlayableRun 진입 경로를 사용할 것.

## 완료 전 근거

- 전체 테스트 1,516개 통과, smoke 세 종류 종료, production build 및 59.9 MB / 60 MB budget 통과.
- 실제 탭으로 첫 네 상대 전투를 완료했다. 타이런트 시드 3은 패배, 시드 7은 강판·보상에 도달했다. 자동 정책 결과를 사람의 재미나 최종 밸런스 근거로 쓰지 않는다.
- 일반 런 보상→지도→이어하기→다음 노드, 실제 세 장 배치·패배·0.5배속, 여섯 전투 크기, 지도 세로 스크롤과 회전 상태 보존을 확인했다.
- 독립 완료 전 코드 검수 GO. 첫 투구 HP 스냅샷과 공개 후보 표시, 타석 변화 메시지까지 점검했다. 브라우저 검증은 총괄이 별도 수행했다.
- 상세 결과·행동 기록·스크린샷: [검증 기록](../qa/encounter-pilot/README.md).
- 브랜치 push 후 Pages 공개 페이지의 네 선택 링크와 실제 전투 로드를 확인하고 결과를 사용자에게 전달한다.
