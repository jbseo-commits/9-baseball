# 9ZONE 전투 UI 재설계 지시서 — 선택에 맞춰 드러나는 정보

작성: 2026-10-13 · 상태: **설계안 / 구현 전**

## 1. 이번에 만드는 변화

사용자는 두 배너를 삭제하는 정도보다 과감한 상업용 게임의 정보 구성을 원했다. 평소에는 경기와 카드가 먼저 보이고, 선택하면 현재 행동의 결과와 위험이 명확해지며, 자세히 알고 싶을 때 충분한 설명을 다시 볼 수 있는 화면을 만든다.

**일반 플레이는 ‘카드 → 코스 → 실행’으로 끝난다. 정보 보기는 자발적인 별도 행동이다.** 모든 플레이어가 정보 보기를 거쳐야 선택할 수 있다면 실패다.

구현의 중심은 다음 여섯 가지다.

1. 상시 코치/도발 행과 중복된 설명을 제거해 경기와 카드의 면적·시각적 우선순위를 회복한다.
2. 비용·커버·지원 상태·현재 위험을 해당 조작과 가까운 고정 위치에 둔다.
3. 카드의 원래 그림을 일정한 크기로 보장한다. 경고가 늘 때마다 그림부터 32px로 줄이는 구조를 폐기한다.
4. 실행부에서 **현재 선택한 플랜 전체**의 비용·예상 효과·막힌 이유를 읽는다. 카드 문구의 재방송을 하지 않는다.
5. 설명·투수 분석·전체 카드 규칙·직전 공 복기는 경기장 영역을 수동으로 전환하는 ‘정보 보기’에 모은다.
6. 선택·지원 준비·투구·결과에 맞춰 내용이 달라져도 카드/존/실행 버튼의 위치는 유지한다.

이 지시서는 게임 코드 구현이나 신규 아트 제작을 요청하는 현 세션의 실행 기록이 아니다. 구현은 다른 세션에서 수행한다. 설계가 상업적 성과나 재미를 입증했다는 주장도 하지 않는다.

## 2. 과거 지시서와의 관계

`original-ui-refinement/UI_CLEANUP_FOLLOWUP.md`의 배너 두 개 정리는 이 설계의 일부로 흡수한다. 이 문서가 충돌하는 **표시 방식**의 최신 기준이다. 과거 문서의 공개 정보·규칙·입력·저장 보호는 계속 적용한다.

| 기존 결정 | 이번 기준 |
|---|---|
| 1A: 카드 앞면 효과/조건/경고 보존 | 의미는 보존한다. 중복 종류 칩과 장문의 동적 오류를 정리하고, 앞면의 짧은 조건·대가·불가 사유와 실행부의 구체적 이유로 역할을 나눈다 |
| 2A: 선택 시 그림 영역 높이 변화 | 외곽과 그림 영역 높이를 모두 고정한다. 같은 크롭 안에서 이미지 확대/강조만 한다 |
| 3A: 기세·흔들림 0을 작게 유지 | 정상값 0의 전용 시각 계기는 제거한다. 0 및 설명은 정보 보기에 남긴다. 활성 효과는 현재 값과 영향이 바로 보인다 |
| 4A: 기존 그림·역할명·기호·색 | 유지한다. ‘공격’처럼 반복되는 일반 종류 칩은 제거하고 ‘준비’처럼 동작이 달라지는 표시는 유지한다 |
| 하단 코치/투수 아바타·대사 행 유지 | 전투 기본 화면에서 행 자체를 제거한다. 조작 도움은 현재 상태 안내/수동 가이드, 캐릭터 대사는 입장·결과의 여유 슬롯으로 옮긴다 |
| 여러 상세/설명 진입 | 본 전투의 수동 설명은 동일한 경기장 정보 보기로 통합한다. 튜토리얼·지도·상점 등의 기존 상세는 별도 보존한다 |

로컬 조사 기준은 `8d3da67`이다. 이 체크아웃은 로컬 origin/main보다 뒤에 있으므로 구현자는 최신 main과 기존 변경을 다시 확인한다. PR #34의 가독성 개선을 처음부터 재구현하지 않는다. hybrid/선택적 덱 실험을 합치지 않는다.

## 3. 화면의 세 구역

### A. 상단 전광판

- 막/경기, B/S/O를 한 번만 표시한다. 이미 CSS로 숨겨진 중복 카운터를 또 삭제했다고 성과로 세지 않는다.
- 작은 로고·HOMEBOUND·소리·BGM 등 상시 버튼을 나열하지 않는다.
- 패 더미 진입 하나와 기존 설정/도움말 진입 하나를 둔다. 소리·BGM·타이틀 복귀는 기존 설정 메뉴 안으로 이동하고 기존 콜백을 사용한다.
- 덱/버림 숫자는 패 더미 버튼에 `더미 8 / 버림 4`처럼 함께 남긴다. 아주 작은 아이콘 두 개로 바꾸지 않는다.

### B. 경기장

- 원래 구장·마운드·홈플레이트·타자/투수·9존의 관계를 유지한다. 원근/구도 전면 교체는 범위 밖이다.
- 투수명과 HP 막대·숫자, 9존의 공개 분포, 주자 다이아몬드를 남긴다.
- 우상단 `.bp-tell`과 좌상단 `.bp-ptype`를 제거한다. 투수명은 남긴다.
- 유효한 보스/엘리트 규칙, 읽기 상태, 활성 기세/흔들림은 아래 배치 표에 따라 짧고 일정한 위치에 표시한다.
- 경기장에는 `정보 보기`와 돌아오는 위치가 명확해야 한다. 기본 진입은 투수명/HP에 붙은 표시된 펼침 버튼이다. 긴 누르기만으로 찾게 하지 않는다.

### C. 손패 + 실행부

- 손패는 겹치지 않는 가로 스크롤이다. 원래 카드 이미지를 유지한다.
- 손패 아래 실행부 위쪽은 고정 높이의 **선택 요약 영역**이다. 별도 코치 행을 그 위에 다시 만들지 않는다.
- 실행부에는 실제 남은 에너지, 현재 플랜 총비용/가능 여부, 공개 범위의 적중권·피해 배율, 현재 입력 안내가 모인다.
- `휘두른다/준비 실행`과 `지켜본다` 버튼은 같은 자리를 유지한다. 상태 안내가 실행 버튼을 밀어내지 않는다.

## 5. 선택 요약은 설명서 대신 현재 플랜을 보여 준다

### 상태별 내용

| 상태 | 요약에 나타날 것 | 동작 |
|---|---|---|
| 미선택 | 남은 에너지, 짧은 `카드와 코스를 고르세요` | 무료 기본 스윙과 지켜보기 접근 유지 |
| 메인 선택 | 실제 비용, 메인 커버/노림, 공개 범위의 적중권·피해 배율 | 다른 설명을 열지 않고 코스 선택/실행 |
| 지원 준비 armed | `지원할 코스 선택` + 기존 플랜 총비용/지원 한도 + 후보 비용 | 기존 메인과 지원은 유지. 후보의 코스를 1탭으로 놓음 |
| 지원 배치 완료 | 전체 플랜 비용/커버, 지원 개수·한도, 현재 공개 효과 | 기존 지원 추가/회수/변경 동작 그대로 |
| 준비 카드 선택 | 비용, 남은 준비 횟수, 실제 효과, 충족/불충족 조건 | 기존 선택→준비 실행. 투구를 새로 진행하지 않음 |
| 불가/비용 초과 | `합계 4 / 에너지 3 · 1 부족` 등 실제 이유 | 엔진/현재 선택 로직이 허용하는 행동만 실행 |
| 투구 중 | 현재 잠금 상태 | 다음 결과나 다음 HP를 미리 보여주지 않음 |
| 결과 | 판정·피해/주자 변화·다음 단계, `이번 공 복기` 진입 | 기존 다음 공/다음 타자/승리 후 진행 |

수치 예시는 레이아웃용이다. 실제 UI는 현재 검증된 `choice`, 비용·배율·공개 구간 계산을 사용한다. `파워 +36`을 `피해 +36`으로 바꾸지 않는다. 현재 불확실한 적중권을 확정 성공률로 바꾸지 않는다.

### 배치 계약

- 에너지/비용, 결과 예측, 현재 조작/문제의 필드를 구분한다. 문구를 `warning || condition`으로 합치지 않는다.
- 한 줄 강제 금지. 좁은 화면에서는 2~3줄을 허용하는 고정 영역을 사용한다. 관련 위험은 카드와 대상 제약 슬롯에도 읽을 수 있어야 한다.
- 선택 요약에 모든 지원 카드의 원문을 누적하지 않는다. 앞면은 카드의 성격/조건, 요약은 현재 플랜의 합계/판정 가능성과 현재 입력을 맡는다.
- 동시 위험을 `+2`, `위험 3개`, 빨간 점만으로 숨기지 않는다. 한 영역에 다 들어오지 않으면 정해진 소유 위치들에 분담한다.
- 실행 버튼 내부의 통계 반복은 제거한다. 버튼은 동작명, 준비/스윙 구분, 실행 가능 여부를 맡는다.
- 단순 hover/focus로 선택 요약의 메인 플랜을 바꾸지 않는다. pointer가 이웃 카드를 지나갔다고 현재 선택 정보가 사라지면 안 된다.

## 6. 카드 그림과 비교 능력을 함께 회복한다

### 카드의 고정 구성

앞면은 **비용 / 기존 그림+범위 / 이름 / 역할 / 고유 효과 / 필수 조건·대가 / 현재 불가 이유**로 구성한다. 일반 공격 종류 칩과 같은 뜻의 중복 문장은 제거한다.

- 초기 제작 후보: 폭 104~112px, 높이 약 168px, 손패 높이 약 176px. 최종 규격은 실제 151종 검수로 정한다.
- 그림의 실제 보이는 영역은 최소 64px 높이를 목표로 고정한다. 같은 뷰포트에서 선택·armed·경고 상태 때문에 그림 영역 높이를 줄이지 않는다.
- 선택/armed/PC hover/focus는 그 크롭 안의 이미지 확대와 경계 강조를 사용한다. 모든 지원 카드를 동시에 키우지 않는다.
- 카드명 2줄, 효과 1~2줄, 필수 조건/위험은 별도 행을 둔다. 핵심 한글은 CSS 12px를 첫 하한 후보로 하고 실제 폰에서 판독 검수한다. 이 수치는 접근성 인증 기준이 아니다.
- 들어가지 않는 내용을 9px로 축소하거나 `overflow:hidden`/말줄임으로 감추지 않는다. 먼저 중복을 제거하고 카드 폭/고정 높이·영역 예산을 조정한다. 그림 하한과 조건을 동시에 만족하지 못하면 해당 레이아웃은 미완료다.
- 색 + 역할명 + 기호를 함께 사용한다. 빈 네모 글리프나 색만으로 사용 불가를 표현하지 않는다.

### 문구를 줄이는 구체적 방식

| 기존 장문/반복 | 앞면 | 선택 요약/정보 보기 |
|---|---|---|
| 모든 후보 카드에 `합치면 2+2=4/3 초과` | 비용 강조 + `지원 비용 초과` | 실제 후보를 탭한 후 발생한 실제 선택 상태에 맞는 합계/이유 |
| `에너지가 부족합니다 · 1/0 필요` | `에너지 부족` + 원래 비용 | 현재 비용/남은 에너지/부족분 |
| `주자가 있어야 쓸 수 있습니다` | `주자 필요` | 준비 선택 시 현재 조건과 실행 불가 이유 |
| 일반 공격 + 역할 장타 | 역할 `장타` | 전체 종류는 상세 |
| 조건부 파워 효과 | `높은 공 파워 +18`처럼 조건을 포함 | 현재 선택에 반영된 값만 표시. 단순 `파워 +18`로 축약 금지 |
| 희생 번트 | 성공률·진루·아웃 지불, 2S일 때 `파울도 삼진` | 선택 중에도 아웃 지불과 현재 위험이 함께 읽힘 |

메인/지원 비용 초과를 카드 ‘사용 불가’와 혼동하지 않는다. 현재 pickSwing은 조건에 따라 지원 대신 메인 교체를 수행할 수 있다. 기존 동작을 유지하고 결과 상태에 맞는 설명을 보여준다. 후보가 지원으로 들어간다는 가정으로 거짓 합계를 표시하지 않는다.

일반 카드도 선택 전에 효과/조건을 비교할 수 있어야 한다. 필수 조건·대가를 전부 ‘선택 후’나 수동 상세로 넘기는 극단적 그림 전용 카드는 금지한다. 151종 기본/강화의 의미 감사표를 갱신해 실제 공간에 들어가는 문구를 확인한다.

## 7. 보스 규칙은 ‘현재 적용’ 중심으로 다시 편집한다

기믹 원문을 통째로 숨기는 대신 **현재 제약의 계산 근거가 읽히는 최소 표현**을 정해진 위치에 둔다.

| 기믹 | 기본 화면에 반드시 남길 현재 정보 | 상세로 이동할 설명 |
|---|---|---|
| pressure | 현재 카운트에 적용되는 사용 코스 증가(+1/+3), 볼 감소, 현재 준비 한도 | 다른 카운트에서의 변화·전체 설명 |
| trick | 이번 공에 적용되는 옆 칸 이동 확률(첫 공 60% / 이후 25% 중 실제 해당 값), 현재 겹치기 한도 | 다른 공의 수치·왜 이동하는지 |
| bluff | 현재 존 밖 볼 가산 +35%p 또는 +45%p, 현재 준비 한도 | 이후 단계 설명 |
| tyrant | 현재 낮은 3코스 가산 +10%p 또는 +20%p, 현재 준비 한도 | 이후 단계 설명. +20은 +10에 추가 합산되는 뜻이 아님 |
| halo | 홈런 외 장타→단타, 현재 겹치기 한도, 현재 단계의 볼 +10%p가 적용될 때 그 값 | 일반/압박/위기 전체 규칙 |
| eclipse | 현재 활성인 직전 노림 반대열 공략/강화와 현재 준비 한도 | 발동 조건과 단계별 원문 |

위 표는 원문 번역 방향이다. 발동 여부·첫 공·국면 판정은 현재 엔진/공개 규칙을 재사용한다. `b.turn===1` 등 추측한 새 조건으로 규칙을 다시 구현하지 않는다. 발동 판정을 안전하게 얻지 못한 규칙은 기존의 정확한 공개 문구를 유지하고 미해결로 보고한다.

배치는 다음으로 나눈다.

- **코스/볼 분포 변화**: 9존 위의 고정 설명 슬롯. 실제 분포의 열지도/공개 수치도 계속 유지한다.
- **피해 변환**: 투수 HP 가까이의 고정 슬롯. halo의 장타 억제 등은 현재 선택이 없더라도 드러난다.
- **준비/지원 제한**: 손패/선택 요약의 한도 표시. 적용 중인 제한을 정보 보기 안에만 넣지 않는다.
- **활성 기세/흔들림**: 기존 소유자 가까운 슬롯에 값과 효과를 짧게. 전체 발생 원인은 정보 보기.

슬롯은 해당 뷰포트의 위치가 고정된다. 발동 시 새로운 행을 끼워 카드나 존을 밀지 않는다. 상태를 시간에 따라 순환 표시하는 ticker, 여러 위험 중 하나만 번갈아 보여주는 방식은 금지한다. 모든 현재 제약이 동시에 읽혀야 한다.

## 8. ‘정보 보기’ — 팝업 대신 경기장 내용을 전환한다

### 표시 방식

사용자가 명시적으로 열면 **경기장 구역만** 분석 화면으로 전환한다. 반투명 배경막, 바깥을 누르면 닫히는 모달, 새 페이지 이동, 손패/실행부를 밀어내는 아코디언을 만들지 않는다.

```text
경기장 구역의 동일한 위치·높이
┌──────────────────────────────────┐
│ 정보 보기                  경기로 │
│ [카드] [투수] [읽기] [이번 공]     │
│                                  │
│ 현재 선택한 설명과 공개 근거       │
│ 긴 원문은 이 영역 안에서만 스크롤  │
│                                  │
└──────────────────────────────────┘
손패·실행부의 자리와 저장된 계획 유지
```

배우/9존 위에 글을 겹쳐 읽게 하지 않는다. 검사 중에는 경기장 렌더가 가려지고 9존 입력은 비활성/inert다. 화면 위에 떠 있는 팝업처럼 움직이거나 크기를 바꾸지 않는다. Pixi/DOM 배우를 불필요하게 재생성해 닫을 때 포즈/타이밍이 초기화되지 않게 한다.

### 진입과 복귀

- 투수명 옆 `정보 ▾` → 투수 탭.
- 읽기 표시의 명시적 상세 버튼 → 읽기 탭.
- 기존 선택 카드 ⓘ, `i`, 우클릭, 480ms 롱프레스 → 해당 카드 탭. 카드 선택/지원 배치는 자동 실행하지 않는다.
- `이번 공 복기` → 이미 공개된 직전 공 탭.
- 패 더미 진입 → 같은 검사 영역에 더미/버림 보기를 제공한다. 탭 수가 늘어나는 것은 선택적 검사에 한정한다.
- `경기로` 또는 Escape → 원래 계획, 메인/노림/지원/armed, 손패 가로 위치, 원래 진입 요소 focus로 돌아간다.

정보 보기 중 손패를 탭하면 **검사할 카드만** 바뀐다. 실제 계획은 바뀌지 않는다. `정보 보기 · 계획은 유지됩니다`라는 상태를 표시하고 검사 카드와 실제 메인의 강조를 구별한다. 가로 스와이프는 카드 탐색이다. 닫으면 열기 전 손패 위치를 복원한다.

정보 보기에서는 스윙·지켜보기·준비·다음 단계 실행을 잠근다. 자발적으로 연 검사에서 벗어나는 명시적 버튼은 항상 접근 가능하다. 정상 전투의 기본 조작에 정보 보기 진입/닫기를 끼워 넣지 않는다.

투구/확정 연출 중에는 검사 진입을 잠근다. 열려 있는 상태에서 엔진이 진행되지 않아야 한다. 카드 `i`/롱프레스/우클릭의 중앙 gesture 라우팅을 고쳐 본 전투의 기존 CardDetailSheet와 검사 영역이 동시에 열리지 않게 한다. 지도/상점/기존 튜토리얼의 상세 동작까지 갈아엎지 않는다.

### 내용

- 카드: 전체 공개 규칙·기본/강화·조건·대가·지원 가능 여부. 이미 바로잡은 문구를 사용하고 과거 watch 손패 9장 등 레거시 오류를 되살리지 않는다.
- 투수: 유형·현재 공개 성향·전체 기믹 규칙·현재/다른 국면을 구분한 설명.
- 읽기: 현재 등급·기여 원천·왜 낱말/구간/정확값인지. 정확값 접근 권한은 기존과 동일하다.
- 이번 공: 실제 플랜·공·판정·HP/주자 변화·기존 복기 조언. 아직 결과가 없는 첫 공은 빈 상태를 명시한다.
- 패 더미: 기존에 공개하던 정보만. 비공개 다음 드로우 순서·RNG를 새로 노출하지 않는다.

모든 상세가 검사 화면 하나에 있기 때문에 4~5탭의 내용이 한꺼번에 늘어나는 전투 HUD가 되지 않는다. 탭은 현재 선택된 한 내용만 보인다. 기본 화면의 위험을 지우고 이 탭으로 숨기는 것은 금지한다.

## 9. 상태 전이와 입력 계약

| 현재 상태 | 입력 | 다음 표시 | 실제 게임 계획 |
|---|---|---|---|
| 일반 미선택 | 카드 탭 | 메인/준비 선택 + 요약 | 기존 처리 그대로 |
| 메인 선택 | 코스 탭 | 커버/공개 예측 갱신 | 기존 처리 그대로 |
| 메인 선택 | 지원 후보 탭 | 기존 로직에 따른 armed 또는 메인 교체 | 기존 처리 그대로 |
| armed | 해당 코스 탭 | 지원 번호/플랜 합계 갱신 | 기존 지원 2탭 완성 |
| 일반 | hover/Tab focus | 내부 아트/포커스 강조 | 선택·요약 변경 없음 |
| 일반 | 명시적 상세 입력 | 정보 보기 | 계획 변경 없음 |
| 정보 보기 | 카드 탭/탭 전환 | 검사 대상/본문 갱신 | 계획 변경 없음 |
| 정보 보기 | 경기로/Escape | 일반 화면/포커스 복귀 | 계획 복원/유지 |
| 일반 실행 가능 | 실행 버튼 | 기존 확정/투구 표시 | 실행 1회만 |
| 투구 중 | 연속 탭 | 입력 잠금 유지 | 중복 실행 없음 |
| 결과 | 다음 버튼 | 기존 다음 공/타자/보상 흐름 | 기존 전이 그대로 |

중첩 button 금지. 카드 안의 조건 태그는 기본적으로 텍스트다. 추가 조작이 필요하면 카드 버튼의 형제 요소나 실행부에 둔다. 준비와 지원의 의미를 아이콘 하나로 합치지 않는다.

터치의 480ms 상세, 8px 이동 취소, 기존 드래그/스와이프 및 ghost-click 보호를 보존한다. 검사 닫기 탭이 실행 버튼으로 전달되거나, 롱프레스 뒤 카드를 자동 선택하지 않아야 한다. 기본 키보드 Tab/Enter/Space를 유지하고 신규 단축키 없이는 정보에 접근 못 하는 구조를 만들지 않는다.

## 10. 투구와 결과에서 과감히 덜어낼 부분

- 스택 확정의 큰 `BATTING PLAN LOCKED` 상자와 통계 재요약을 본 전투에서 없앤다. 기존 `commitBeat` 입력 잠금/타이머와 엔진 실행 횟수는 유지한다. 720ms를 새 밸런스/속도 규칙으로 바꾸지 않는다.
- 투구 중에는 배우·공·충돌을 먼저 보게 한다. 소유자 상태/버튼은 입력 잠금을 정확히 나타내고 결과를 미리 발표하지 않는다.
- 판정, 실제 공 위치, 실제 HP 변화, 타자/주자 이동은 기존 시점에 명확하게 보여준다. 효과를 숨겨 ‘깔끔한 화면’만 만들지 않는다.
- 3열 `내 선택→실제 공→다음엔` 설명을 매 공 강제하지 않는다. 손패가 원래 결과용 공간으로 바뀌는 구간 안에 핵심 결과와 `이번 공 복기`만 둔다.
- 투수의 개성은 기존 아트·입장 포즈·결과 대사로 유지한다. 대사는 규칙/피해/주자 이동 슬롯과 경쟁하지 않을 때만 표시하고, 중요한 결과가 많으면 생략한다. 텍스트 대사가 사운드 자막이라면 접근성 설정/자막 요구를 별도로 보존한다.
- 처음 하는 플레이어에게도 자동 가이드 dialog를 기본으로 띄우지 않는다. 기존 도움말에서 명시적으로 `전투 가이드`를 선택하면 볼 수 있게 한다. 삭제된 `.bp-tell`/코치 행을 가리키는 단계를 정리하고 기존 ‘봤음’ 저장 키를 초기화하지 않는다.

## 11. 공개 정보와 착탄 시점은 모든 표시의 공통 계약

한 공개 view model을 일반 HUD/카드/선택 요약/검사 화면/aria-label/기믹 장식에 공유한다. 새 inspector만 정확한 미래 상태를 읽게 해서는 안 된다.

- 읽기 0: 기존 낱말/명암 정보. 읽기 1: 기존 구간. 읽기 2 및 기존 공개 예외: 허용된 정확값.
- 공개 숫자를 단순히 숨기는 것과 비공개 숫자를 새로 드러내는 것을 구별한다. 상세는 숨겨진 결과를 여는 치트가 아니다.
- 착탄 전에는 `pre`, `hpWas`, shownCount/shownBases, 이전 기세/흔들림, shownGimmickPhase를 사용한다.
- 실제 코스·판정·피해·국면 변화·KO는 기존 착탄/결과 타이밍 뒤에만 보인다.
- 현재 적용 수치는 ‘현재’, 다른 단계 설명은 ‘다른 단계’로 구분한다. 앞으로 일어날 국면/확정 결과처럼 읽히지 않게 한다.
- 확률 구간 상한 100% 보정, 번트/스퀴즈 계열 분류, singles/bunt 강화 예외 등 기존 수정을 보존한다.

UI를 위해 확률 추첨·RNG·카드 정의·엔진 비용·피해·덱·주자 규칙·저장 스키마를 변경하지 않는다.

## 12. 면적과 가독성 예산

픽셀 값은 초기 제작 후보다. 같은 뷰포트에서 선택 전후 hitbox가 이동하지 않는 계약은 필수다.

| 구역 | 375×667 초기 예산 | 조정 원칙 |
|---|---:|---|
| 전광판 | 44px | 작은 버튼 6개 대신 큰 진입 2개. 터치 목표 44px 수준 확보 |
| 손패 | 176px | 카드 후보 168px, 그림 영역 64px 이상 목표 |
| 실행부 | 128px | 요약 약 64px + 버튼 약 56px + 여백. 조작/위험은 축소 글씨로 맞추지 않음 |
| 경기장 | 남은 약 319px | 실제 usable height·safe area·상단 앱 헤더가 있으면 다시 계산 |

계산은 첫 작업용이며 실제 브라우저 바를 포함한 구현 성공을 보장하지 않는다. 최종 수치는 경기장 좌표와 함께 캡처/실측으로 제출한다.

- 375×667, 390×844, 360×640 및 실제 주소창 노출 상태를 확인한다. PC는 넓은 창 안의 기존 세로 iframe 내부에서 검수한다.
- 레이아웃 높이는 현재 실제 뷰포트를 기준으로 하고 safe area를 반영한다. 전역 body overflow를 바꿔 화면에 억지로 맞추지 않는다.
- 더 작은 높이에서 먼저 제거할 것은 장식·중복 간격이다. 필수 위험·실행 버튼·9존 hitbox를 지우지 않는다.
- 정보 보기 내부 세로 스크롤은 허용한다. 일반 전투 세로 스크롤, 이중 축 설명 스크롤, 손패 위로 솟는 패널은 금지한다.
- 9존 각 터치 영역·정보 닫기·실행 버튼은 실제 터치로 검수한다. 투수/타자 발 위치와 플레이트 구도가 훼손되지 않아야 한다.
- reduced-motion에서는 자동 반짝임/확대 전환을 줄인다. 상태/조건/위험은 애니메이션을 보지 않아도 읽힌다.
- 큰 글자/브라우저 확대 시 핵심 설명은 검사 화면에서 한 방향으로 읽고 돌아올 수 있어야 한다. 본 작업만으로 전체 XAG 충족이라고 보고하지 않는다.

## 14. 구현 순서와 예상 파일

1. 최신 main/AGENTS/현재 diff/관련 UI를 확인한다. 동일 시드의 일반·선택·지원·최악 위험·결과를 변경 전 캡처한다.
2. UI 표시 항목마다 `상시 / 맥락 / 정보 보기 / 제거`와 현재 공개 데이터 원천을 표로 고정한다. 아직 모르는 규칙을 임의 축약하지 않는다.
3. 전광판·코치 행·유형/예고·정상 계기·결과 복기/확정 상자를 정리하고 고정 그리드/소유 위치를 만든다.
4. 카드 내부 고정 아트·핵심 문구·조건 태그·동적 경고와 선택 요약을 함께 구현한다. 그림만 크게 만들고 조건을 나중에 붙이지 않는다.
5. 동일 경기장 영역의 수동 검사와 모든 진입/복귀/gesture 라우팅을 구현한다.
6. 기믹별 ‘현재 적용’ 수치, 선택/armed 예외, 착탄 전 공통 view model을 검수한다.
7. 자동/실브라우저/사람 검수 결과를 구분해서 제출한다. 부분 단계 성공으로 전체 완료라고 보고하지 않는다.

예상 파일:

- `BallparkBattle.jsx`: 본 전투 구성/상태별 표시. 대형 컴포넌트를 이유 없이 전면 리팩터링하지 않는다.
- 신규 전투 전용 UI helper/컴포넌트: 공개 표시 모델, 선택 요약, 경기장 정보 보기. 이름은 저장소 관례에 따른다.
- `card-face.js` 및 기존 카드 의미 감사표: 축약 문구·조건/경고 의미. `card-art.js` 원본 매핑 보존.
- 새 범위 제한 CSS: 기존 main의 `battle-readability.css`를 덮어쓰지 않는다. 중복 규칙을 확인한 부분만 좁게 정리한다.
- `BallparkCoach.jsx`: 자발적 가이드 진입/현재 타깃. 삭제된 타깃을 남기지 않는다.
- `App.jsx`, `CardDetailSheet.jsx`: 본 전투 수동 상세 라우팅 어댑터. 다른 화면의 sheet까지 바꾸지 않는다.
- 관련 UI/gesture/공개 정보 테스트. 레거시 BattleReadout는 이 화면의 정리 대상이라고 추정하지 않는다.

## 15. 필수 검수 시나리오

### 자동/실브라우저로 확인할 계약

- 미선택·메인·armed·지원 배치·준비·불가·결과에서 카드/존/실행 좌표가 각 뷰포트 기준으로 일정하다.
- 어떤 일반 카드 탭도 검사/dialog를 자동으로 열지 않는다. 기존 지원 후보→코스 2탭, 실행 1회 계약 유지.
- 2S 번트/스퀴즈 + 에너지 부족에서 성공/아웃 지불/파울 삼진/불가 이유가 함께 읽힌다. 강화 예외도 확인.
- 주자 필요 준비 + 준비 소진 + 부족 에너지 등 여러 문제가 있어도 조건 하나가 사라지지 않는다.
- 메인 교체로 처리되는 지원 후보를 지원 배치로 오표시하지 않는다.
- 151종 기본/강화 앞면의 의미, 조건, 경고, 아트 하한을 대조한다. nonempty 문자열 검사는 의미 검수의 대체가 아니다.
- 각 기믹의 일반/압박/위기와 카운트/첫 공 예외에서 현재 필요한 숫자·한도가 보인다. 다른 단계는 명확히 구분한다.
- 검사 열기→카드 여러 장 보기→닫기에서 계획/armed/손패 위치/focus가 유지된다. 일반 실행은 검사 중 잠긴다.
- 키보드·우클릭·480ms 롱프레스·이동 취소·닫기 직후 탭을 검증한다. 숨겨진 존은 클릭/Tab 대상이 아니다.
- 정상 HUD, 선택 요약, 검사, aria, 장식 모두 착탄 전 미래 HP/국면/코스/KO를 드러내지 않는다.
- 결과 판정·피해·타자/주자 이동과 다음 단계가 정상이다. 중요한 결과가 대사에 덮이지 않는다.
- 실제로 넘치는 지도에서 스크롤하고 전투→보상→시설→다음 경로→저장 후 이어하기를 수동으로 완주한다.
- 필수 전체 테스트·관련 회귀·smoke 4종·production build·dist 예산을 실행한다. 기존 987건 등 과거 결과를 새 검증으로 인용하지 않는다.

### 사람이 판단할 상업용 화면의 합격 조건

처음 보는 사람과 기존 플레이어가 각각 동일한 손패의 미선택/선택 화면을 사용한다. 측정값은 실제로 관찰한 것만 기록한다.

1. 비용·역할·고유 효과로 카드 2~3장을 비교하고, 자세한 설명 없이 기본 플랜을 실행할 수 있다.
2. 주자 조건·희생 아웃·2S 파울 삼진·에너지 초과가 있는 카드를 실행하기 전에 그 위험을 말할 수 있다.
3. 투수 기믹 때문에 현재 카드/지원/코스 선택이 달라지는 이유를 기본 화면에서 찾는다.
4. 처음 보는 긴 규칙은 정보 보기에서 찾고, 닫은 뒤 원래 플랜을 잃지 않고 계속한다.
5. 기존보다 일상 선택마다 상세를 여는 횟수가 증가하지 않는다. ‘숨겨서 단순해 보일 뿐’이라는 반응은 실패 근거다.
6. 원래 카드 그림이 더 잘 보이면서도 작은 폰에서 핵심 문구를 읽는다. 비슷한 카드의 구별 여부를 확인한다.

판독 시간·오탭·상세 진입 횟수·위험을 못 본 사례를 전후 비교하되 표본/기기/경험을 함께 기록한다. 임의 목표 수치를 달성했다며 상업적 성공으로 환산하지 않는다.

## 16. 제출물과 완료 기준

- 동일 시드/동일 뷰포트의 전후 캡처: 미선택, 메인, armed, 복합 위험, 보스 규칙, 정보 보기, 결과.
- 151종 문구/조건/경고 대조표 및 제거/이동 항목별 회수 경로 목록.
- 정확한 테스트 명령/종료 결과, 실제 브라우저 확인, 미확인 실기기 항목을 구분한 검증 기록.
- 필수 정보를 보기 위해 추가된 탭 수가 0인지, 지원 2탭과 일반 실행 흐름이 유지되는지.
- 일반 전투 스크롤 0, 카드/존/버튼 좌표 안정, 그림 영역 고정, 미래 정보 무노출.
- 자동 팝업 없이 선택에 따라 정보가 드러나고, 자발적 검사에서 충분한 근거를 찾은 뒤 복귀할 수 있을 때 설계 구현 완료다.

별도 요청 없이 GitHub push·PR 생성·main 병합·배포하지 않는다. 새로운 카드/유물/덱 다양성·규칙 변경은 이번 작업에 포함하지 않는다. 화면 정보 재설계와 ‘덱이 달라도 플레이가 비슷함’ 문제는 별도 과제로 보고한다.

## 17. 참고 원칙과 해석 범위

- [NN/g — Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/): 보조 설명을 필요한 때 접근하게 만드는 원칙을 참고했다. 이 게임의 수동 검사와 위험 보존 규칙은 본 설계의 판단이다.
- [Xbox Accessibility Guideline 112 — UI navigation](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112): 일관된 위치·입력·focus와 명확한 복귀 경로를 참고했다.
- [Xbox Accessibility Guideline 101 — Text display](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/101): 실제 화면의 텍스트 판독·확대·표시 환경 검수를 참고했다. 본 문서의 CSS 후보 크기를 가이드 충족으로 등치하지 않는다.

확인일 2026-10-13. 특정 상업 게임의 실제 플레이 UI를 복제하거나 검증했다는 의미가 아니다. 구현 세션에는 [시작 프롬프트](IMPLEMENT_THIS.md)와 이 문서를 함께 전달한다.
