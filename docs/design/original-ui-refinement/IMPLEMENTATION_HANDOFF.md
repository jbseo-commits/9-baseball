## 1. 목표와 사용자 결정

**원래 게임 화면과 카드 선택 중심의 플레이를 유지하면서, 손패를 훑고 행동을 결정하기 쉽게 만든다. 카드 안의 기존 그림은 살린다.**

사용자는 이전 hybrid 화면과 카메라 재설계를 채택하지 않았다. 계속 세로로 스크롤해야 하는 화면, 원래 구도를 무너뜨리는 재배치, 카드 선택 때 별도 팝업을 강제로 띄우는 방식도 원하지 않는다.

커뮤니티 피드백에서 이번 작업으로 다룰 문제는 다음 세 가지다.

- 작은 화면에 정보를 동시에 많이 보여줘 복잡해 보인다.
- 작은 카드들의 그림·색·구도가 비슷해 손패를 하나씩 읽어야 한다.
- 확대 표현을 넣더라도 카드 선택과 지원 배치의 조작 흐름을 방해하면 안 된다.

이번 작업의 성공은 **더 적은 시선 이동으로 카드 역할·비용·핵심 효과·사용 가능 여부를 읽는 것**이다. 이전의 “매번 비슷한 시작”, “덱이 달라도 하는 일이 비슷함”이라는 게임성 문제는 별도 과제다. UI 변경으로 덱 다양성이 해결됐다고 보고하지 않는다. 테스트 통과나 캡처만으로 재미 또는 상업적 마스터피스를 입증했다고 표현하지 않는다.

## 4. 1A 상세 — 카드 앞면의 정보 계층

### 항상 보이는 정보

| 우선순위 | 정보 | 배치·표현 |
| --- | --- | --- |
| 1 | 에너지 코스트 | 좌상단 고정 배지. 준비 0코스트도 명시 |
| 1 | 사용 불가/합산 에너지 초과/위험 | 눈에 보이는 짧은 문장. 색상만으로 전달하지 않음 |
| 2 | 카드 이름, 강화 `+` | 이름 유지. 긴 이름은 최대 2줄을 우선 검토 |
| 2 | 범위 | 우상단 기존 3×3 미니맵. 현재 노릴 존·범위의 의미 유지 |
| 2 | 역할 | 공격/준비 유형 + 역할명·기호·기존 색 계열 |
| 2 | 핵심 효과 | 동작 또는 이득을 나타내는 한 줄. 필수 조건을 빼서 의미를 바꾸지 않음 |
| 3 | 기존 그림 | 카드 내부에서 충분히 보이게 유지. 경고가 있으면 그림 공간부터 조정 |

앞면에서 줄일 것은 중복되는 범위 문장, 긴 분위기 문구, 전체 강화 설명, 부차적 효과의 나열이다. 한 줄 목표는 필수 위험을 숨기라는 뜻이 아니다. 필수 정보가 함께 있으면 경고 영역을 추가로 확보한다.

### 의미 작성 규칙

1. `cards.js`, `cards-v16.js`의 정의와 실제 엔진 조건을 확인한다. `cardText()`·`upgradeText()`·`gives[0]` 하나를 무조건 진실로 취급하지 않는다.
2. 범위는 미니맵이 이미 보여주므로 효과 문구에서 같은 “가로 3존”을 반복하지 않아도 된다. 다만 조건부 범위나 예외는 없애지 않는다.
3. 숫자의 단위를 유지한다. `파워 +36`, `투수 HP 압박 +50%`, `주자 +1루`를 서로 바꾸지 않는다.
4. 조건부 효과는 조건과 함께 쓴다. `높은 공 파워 +18`을 `파워 +18`로 바꾸면 실패다. 메인 전용 효과를 모든 지원 카드에도 적용되는 것처럼 표현하지 않는다.
5. 강화 `+`는 표식만 붙이는 것으로 끝나지 않는다. 앞면에 표시한 효과가 강화로 달라지면 수치·지속 시간·정보 범위도 실제 정의에 맞춘다.
6. 같은 역할 카드에서도 고유 효과를 남긴다. 모든 카드를 “파워 증가” 또는 “준비”로 평탄화하지 않는다.
7. 핵심 효과/조건/대가의 핵심 단어를 `…`나 `overflow:hidden`으로 숨기지 않는다. 짧게 다시 쓰거나 그림 높이를 조정한다. 전체 내용이 aria에만 있으면 실패다.

### 필수 예외와 검수 예시

아래 문구는 의미 기준이다. 띄어쓰기와 축약은 가능하지만 규칙을 바꾸면 안 된다.

| 카드/상황 | 앞면에서 유지할 의미 | 주의 |
| --- | --- | --- |
| `place` 정타 노림 | `정타 HP +50%` | 메인의 정확 적중 조건과 지원의 의미를 대조 |
| `slug` 당겨 넘기기 | 기본 `파워 +36`, 강화 `파워 +54` | `cardPower()` 기준. 피해량 보장으로 쓰지 않음 |
| `rally` 주자 연결 | `안타 → 주자 +2루` | 기존 주자의 진루. 즉시 주자를 생성하는 효과가 아님 |
| `setup` 타이밍 맞추기 | 코스트 0, 집중 +1 / 강화 +2 | 에너지와 준비 횟수는 다른 자원 |
| `watch` 작전 확인 | 카드 2장 / 강화 3장 뽑기 | 기존 강화 문구의 “손패 최대 9장”을 새 요약에 복제하지 않음 |
| `scout` 릴리스 간파 | 높이·볼 간파 / 강화 높이·안팎 간파 | 구종을 알려준다고 쓰지 않음. 드로우 부효과는 수동 상세에서 정확히 |
| `flow` 히트앤드런 사인 | 안타 → 기존 주자 +1루 / 강화 +2루, `주자 필요` | 주자가 없을 때 불가사유 시각 표시 |
| `bunt` 희생 번트 | `진루 +1 · 아웃 +1`, 희생 70% / 강화 85% | 2스트라이크면 `파울도 삼진`. 성공 시 지불하는 아웃을 숨기지 않음 |
| `squeeze` 스퀴즈 | `진루 +1 · 아웃 +1`, 희생 82% / 강화 92% | `kind==='bunt'`만 검사하면 누락. `d.bunt` 계열 전체 처리 |
| `highLane` 등 코스 조건 카드 | 높은 공 등 조건 + 파워 효과 | 강화 정규식으로 조건부 효과를 기본 파워로 덮지 않음 |
| 단타 고정/번트 계열 강화 | 실제 강화 효과·예외 | 일반 `공격이면 +18` 문구를 일괄 적용하지 않음 |
| `lure` 코스 조정 | 다음 스윙 범위 확장 / 강화 타석 동안 유지 | 소멸·지속 시간 및 범위 증가에 따른 장타력 손실을 검수 |

현재 엔진의 일반 드로우 상한은 `HAND_MAX=5`, 지켜보기 보너스의 상한은 `V10_TAKE_HAND_MAX=6`이다. UI를 문구에 맞추려고 손패 상한을 9로 바꾸지 않는다. 최신 소스에서 다시 확인한다.

### 조건·대가·불가사유는 동시에 성립할 수 있다

- 조건 예: 주자 필요 / 2스트라이크 전용 / 스트라이크 필요 / 초구 전용 / 주자 없을 때.
- 대가 예: 아웃 지불, 소멸, 제한되는 결과, 범위를 넓힐 때의 장타력 손실.
- 현재 불가사유 예: 준비 횟수 소진, 현재 에너지 부족, 지원 합산 비용 초과.
- `2+2=4/3 초과`처럼 합산 초과는 현재 선택과 실제 에너지 한도에 따라 계산한다. 금지 표시만 넣지 않는다.
- **현재 후보의 `warning || face.condition`는 보완 대상이다.** 에너지 초과 때문에 번트의 2스트라이크 파울 삼진이 사라지는 식으로 앞의 경고가 뒤의 위험을 덮으면 안 된다. 조건·대가·불가사유를 구조적으로 구분한 뒤 모두 보이게 구성한다.
- `widthPenalty`는 기존 엔진에서 커버 1칸 초과당 파워 7을 줄인다. 이 수치를 변경하지 않는다. 앞면의 범위 강화 문구가 무조건 장타 이득으로 오해되지 않도록 기존 예고·상세와 함께 검수한다.

현재 기준 카드는 코어 16 + V16 135 = **151종**이다. 소스의 “V16 124” 주석은 카드 수의 근거로 쓰지 않는다. 새 세션에서 실제 `CARDS` 키 수를 확인하고, 기본/강화 전부를 다음 열로 대조한 기록을 남긴다.

`kind | 이름 | 기본 요약 | 강화 요약 | 조건 | 대가/위험 | 불가사유 조합 | 근거 필드 | 검수 결과`

“151종 모두 문자열이 있음”은 누락 탐지에만 유효하다. 올바른 효과·조건·강화를 검증한 근거는 아니다. 전체 수동 상세에도 틀린 기존 문구가 있으면 엔진 근거가 있는 표시 문구만 좁게 고치고 변경 내역을 명시한다. 전체 규칙·덱 화면의 리팩터링으로 확대하지 않는다.

## 5. 2A 상세 — 확대와 입력 계약

### 상태별 표현

| 상태 | 내부 그림 | 버튼 외곽/기능 |
| --- | --- | --- |
| 평상시 | 기본 크롭 | 기존 크기·위치, 즉시 선택 가능 |
| 메인 선택 | 내부 확대 | 메인 표시, 존 선택 가능 |
| 지원 준비 `armed` | 내부 확대 | 다음 존 탭으로 지원 추가 |
| 배치된 지원 | 지원 번호·상태 명시 | 손패 여러 장을 동시에 크게 밀어내지 않음 |
| PC hover/focus | 내부 확대와 식별 가능한 focus | 선택 상태를 자동 변경하지 않음 |
| 조건/경고 있음 | 경고 공간 우선, 고정 크롭 안에서 작은 확대 가능 | 위험 문구 끝까지 보임 |
| 투구 진행/잠김 | 기존 비활성 처리 | 중복 실행·중복 소비 없음 |

현재 후보의 수치: 카드 외곽 `98×138px`, 손패 행 기존 `148px`, 일반 그림 `54px` → 메인/armed/focus/hover `66px`; 조건·경고 카드는 그림 `40px`를 유지하고 내부 이미지만 약 `1.06` 확대한다. 준비 카드도 후보에서는 폭 98px로 통일했다.

이 수치는 검토를 시작할 때의 후보값이다. 이미 승인된 최종 미술 규격은 아니다. 작은 글씨를 더 줄여 맞추지 말고 정보 우선순위와 기존 행 높이 안에서 조정한다. 현재 후보의 이름/효과 11px, 역할 배지 9px, 조건 10px도 실제 휴대폰에서 읽히는지 확인해야 한다. 기존 가독성 스타일의 최소 크기 계약을 덮는지 함께 검토한다.

### 입력별 합격 시나리오

1. 모바일 공격 카드 탭 → 메인 선택. 이 탭 자체로 그림이 커진다. 상세 팝업은 열리지 않는다.
2. 존 탭 → 기존 노림·커버 표시. 실행 버튼 → 기존 투구 진행.
3. 메인을 둔 상태에서 다른 공격 카드 탭 → armed. 존 탭 → 그 존을 기준으로 지원 추가. 별도 확인 버튼 없음.
4. 기존 지원 제거·교체·스택 한도·번트 겹치기 제한·맨손 스윙 동작 유지.
5. 준비 카드는 기존 선택/실행 버튼 흐름 유지. 손패를 가로로 밀어도 카드를 의도치 않게 사용하지 않음.
6. PC에서는 fine-pointer hover와 키보드 focus만으로 내부 확대. hover가 선택/지원 준비를 일으키면 실패.
7. 탭·drag·수평 스와이프 도중 손패 버튼이 이동하거나 이웃 카드/9존/실행 버튼을 덮지 않음.

### 수동 상세 유지

선택 카드의 ⓘ, 카드에서 `i`, 우클릭, **480ms 롱프레스**는 기존 상세 진입 수단으로 유지한다. 8px 초과 이동 시 롱프레스 취소, 기존 9px drag 시작과 capture/ghost-click 보호를 보존한다. 롱프레스 후 즉시 닫기, 롱프레스 중 스크롤, 멀티터치·pointercancel 회귀도 확인한다.

상세는 사용자가 요청할 때만 열린다. 카드 선택/호버마다 새 모달·툴팁을 만들지 않는다. 기존 ⓘ를 기믹 설명 버튼으로 바꾸지 않는다. 상세를 닫으면 이전 카드·존·지원 선택이 유지돼야 한다.

PC는 최상위 창이 가로여도 `PortraitFrame`의 세로 iframe 안에서 게임이 실행된다. CSS의 `orientation`은 실제 렌더링 문서 기준으로 확인한다. **후보 CSS가 portrait media 안에 있다는 이유만으로 PC 지원 완료 또는 실패를 단정하지 않는다.** 실제 iframe 안의 hover/focus·computed style·버튼 좌표로 입증하고 필요한 범위만 수정한다.

`prefers-reduced-motion: reduce`에서는 확대 이동 애니메이션을 줄이거나 제거한다. focus 표시는 남긴다.

## 6. 3A 상세 — HUD와 위험 규칙

### 표시를 줄이는 범위

| 상태 | 유지할 표시 |
| --- | --- |
| 기세 0 | 작고 조용한 `기세 0`. 빈 장식 핍과 ×1.0의 중복 강조 축소 |
| 기세 > 0 | 단계와 실제 피해 배율, 기존 상승/꺼짐 피드백 |
| 흔들림 0 | 작고 조용한 `흔들림 0` |
| 흔들림 > 0 | 현재/상한 및 `볼 증가 · 읽기 +1` 등 현재 영향 |
| 모든 전투 상태 | 투수 HP, B/S/O, 에너지, 주자·베이스, 공개 존 정보, 선택 카드와 지원, 실행/지켜보기 |

0이라는 상태 자체를 삭제하지 않는다. 어떤 효과가 꺼져 있는지 알 수 있어야 한다. 이미 계산된 화면 표시용 `momentum`, `shaken`, `shownCount`, HP 이전값을 사용한다. 엔진은 투구를 먼저 계산할 수 있으므로 착탄 전 raw state를 사용하면 다음 피해/기세/흔들림/보스 단계가 새어 나올 수 있다.

기세 배율·흔들림 상한은 기존 헬퍼를 사용한다. 현재 상한을 모든 상대에 3으로 하드코딩하지 않는다. 확률·간파·유물의 공개 범위도 기존 계산 그대로 유지한다. aria-label, data attribute를 새로 추가할 때도 미공개 미래 정보를 넣지 않는다.

### 기믹: 항상 보일 위험과 펼쳐 볼 설명

원본 기준은 `src/duel/gimmick.js`의 공개 설명·phase·`gimmickRules()`다. 이름 + 현재 플레이를 바꾸는 짧은 규칙 + 현재 적용 중인 제한을 기본 상태에서 보여준다. 긴 설명은 기존 패널 안의 `규칙 자세히`처럼 **명시적 인라인 펼침**을 사용한다. 자동 팝업 없음.

현재 후보의 짧은 `gimmickHints`는 일부 공개 숫자를 생략한다. 다음 세션에서 아래처럼 의사결정에 중요한 정보가 빠지지 않게 다듬는다. 새로 숨은 확률을 공개하는 것이 아니라 원래 공개된 규칙을 보존하는 것이다.

| 기믹 | 기본 상태에서 남길 공개 의미 | 활성 phase에서 추가로 남길 것 |
| --- | --- | --- |
| pressure | 1S 코스 +1 / 2S 코스 +3, 볼 감소 | 준비 1회 제한 |
| trick | 예고 인접 칸 이동, 첫 공 60% / 이후 25% | 겹치기 3장 제한 |
| bluff | 존 밖 볼 +35%p | +45%p로 변경, 준비 1회 제한 |
| tyrant | 낮은 3코스 +10%p | 준비 1회, critical 낮은 코스 +10→+20%p로 변경(추가 합산 아님) |
| halo | 홈런 외 장타 → 단타 | 겹치기 3장, critical 볼 +10%p |
| eclipse | 직전 노림 반대 열 공략 | 반대 열 강화, critical 준비 1회 |

현재 phase 이전에 앞으로 생길 제한을 활성 상태로 표시하지 않는다. `steady >60%`, `pressured ≤60%`, `critical ≤30%`의 기준도 기존 헬퍼와 대조한다. 후보의 임의 HP 분기와 엔진 기준이 다른 값이 되면 안 된다.

기믹 숫자를 남길 공간이 부족하면 중복 설명을 제거하고 줄바꿈·짧은 표기를 먼저 검토한다. HP 패널이 구장·9존을 덮거나 전투 전체 높이가 늘어나면 실패다. `규칙 자세히`를 열었을 때도 실행 버튼이 밀려나거나 문구가 잘리지 않는지 검증한다. 필요하면 그 설명 영역만 제한된 스크롤을 쓰되 기존 경로 스크롤에는 영향이 없어야 한다.

## 7. 4A 상세 — 기존 그림과 역할 식별력

- `cardArtFor()`와 기존 카드 시트 fallback을 유지한다. 원본 에셋을 삭제·재인코딩·생성 이미지로 일괄 교체하지 않는다.
- 카드별 초점은 `cardArtFocusFor()`의 기존 object-position을 우선 사용한다. 인물·배트·공이 잘려 역할이 더 모호해지는 카드만 조정한다.
- 코스트는 좌상단, 범위는 우상단, 이름·유형·역할·효과 순서를 카드마다 일관되게 유지한다.
- 선택/지원 번호는 코스트·범위·조건과 겹치지 않는다. 후보에서는 상단 코스트와 범위 사이로 옮겼다. 여러 자리 번호·준비 표식도 확인한다.
- 역할은 텍스트 + 기호 + 기존 색을 함께 사용한다. 기호가 글리프 지원 문제로 빈 네모가 되는지 실기기에서 확인한다. 기호는 의미 전달이 중복되면 `aria-hidden` 처리하고 역할명은 읽힌다.

| 역할 | 후보 기호 | 색 계열 방향 |
| --- | --- | --- |
| 정타 | ◎ | 기존 red |
| 장타 | ↗ | 기존 gold |
| 범위 | ▦ | 기존 bone |
| 진루 | ◇ | 기존 brass |
| 생존 | ⊥ | 기존 bone, 역할명·기호로 범위와 구분 |
| 집중 | ＋ | 기존 cyan |
| 수급 | ↻ | 기존 teal |
| 관찰 | ◉ | 기존 purple |

이 기호는 현재 후보다. 읽기 어려우면 기존 아이콘 체계에 맞는 코드/SVG 기호로 좁게 교체할 수 있다. 새 희귀도·새 역할 규칙을 만들지 않는다. 컬러풀한 테두리·과한 광택·입자 효과로 식별 문제를 덮지 않는다.

실행 버튼은 원래 약 68px 높이 안에서 동작명 + 적중권/피해 배율/에너지 예고를 보여준다. 후보가 375px에서 예고 3개를 2줄로 맞춘 보정도 포함한다. 각 값이 버튼 밖으로 나가거나 글씨를 극단적으로 줄여야 하면 완료가 아니다.

## 9. 별도 인접 수정 — 공개 확률 표시 112% 오류

여러 존의 공개 구간 상한을 더하면 후보 작업 중 `적중권 42–112%`가 재현됐다. `tests/ballpark-battle.test.jsx`의 seed 90211, tableSetter + relayBat fixture로 **수정 전 상한 112 테스트 실패**를 확인했다.

현재 후보는 공개 구간 상한에 `Math.min(1, hi)`를 적용한다. 이는 UI 표시 보정이다. 확률 추첨·읽기 단계·RNG·덱·엔진 수치를 바꾸지 않는다. 재현 fixture의 카드 배열을 실제 시작 덱으로 옮기지 않는다.

다음 세션은 이 변경을 카드 가독성 변경과 구별해 기록하고, 구간 모드에서 100% 이하인지 및 정확 확률 모드가 기존 값을 유지하는지 확인한다. 별도 커밋으로 분리해도 된다. 이 오류를 근거로 새로운 확률 계산 시스템을 만들지 않는다.

2. **기준 기록:** 동일한 공개 상태/손패를 사용한 원래 main 화면과 후보 화면의 375×667, 390×844 비교 근거를 마련한다. 테스트 fixture와 실제 캠페인을 구분한다. 사용자의 실세이브를 덮어쓰지 않는다.
3. **영향도/계획 검토:** 9축 영향도를 최신 상태로 확인하고 독립 reviewer에게 범위·계약·위험을 전달한다. 동시에 쓰는 구현자는 한 명만 둔다.
4. **문구부터:** 카드 기본/강화 전체 대조표 작성. 핵심 효과·조건·대가·불가사유 조합을 결정한다. 의미가 확정되지 않은 상태에서 CSS로 억지 축약하지 않는다.

6. **HUD/기믹:** 0/활성/최댓값, 투구 전/착탄 전/후를 나눠 표시한다. 공개 위험 숫자·phase 제약 보존.
7. **회귀:** 관련 자동 테스트 → 필수 실제 플레이 → 전체 테스트·smoke·production build·dist budget. 실패 항목은 근거를 남기고 같은 오류 두 번째에는 독립 검토를 받는다.
8. **인수 검토:** reviewer에게 최종 diff, 실제 캡처, 실행 로그, 미확인 항목을 전달한다. 해당 증거를 문서에 기록한다.
9. **보고:** 변경 내용·보존한 흐름·실행한 검증·남은 한계를 사용자에게 보여준다. 게시 요청이 있는 경우에만 해당 범위의 브랜치 PR/프리뷰 절차를 수행한다.

- 기믹의 현재 숫자·제한이 접힌 상태에서도 보이고 펼침은 수동임.

## 14. 로컬 환경 주의

기존 후보 폴더에서 pnpm 설치 중 `database disk image is malformed` 오류가 있었고, 당시 불완전 설치는 `.qa-incomplete/node_modules`에 보존했다. 현재 `node_modules`는 `C:\Users\정현아\9-baseball-selective-integration-20261012\node_modules`로 연결된 **junction**이다. 같은 lockfile의 설치를 재사용한 상태다.

- 이를 게임 소스의 의존성 변경으로 오해하지 않는다. `package.json`/lockfile을 이유 없이 바꾸지 않는다.
- 다른 컴퓨터에서는 프로젝트의 정상적인 frozen-lockfile 설치를 사용한다. 로컬 절대 경로 junction을 배포물에 넣지 않는다.
- junction 대상이나 전역 pnpm store를 통째로 삭제·정리하지 않는다. 환경 수리가 필요하면 영향 범위를 별도로 확인한다.

- 이 문서 작성 시 후보 확인용 4324 dev server와 임시 검증 탭/viewport override는 정리했다. 필요할 때 자신의 서버를 다시 시작한다. 다른 세션의 4319/4321/4323 서버는 정리 대상이 아니다.

## 15. 제출과 게시 경계

현재 사용자 요청은 **상세 지시서 작성**이며, 이 문서 작성 세션에서는 GitHub에 업로드하지 않는다. 구현 세션에서 사용자가 구현을 맡기면 이 명세를 기준으로 작업한다. 이 문서만으로 현재 세션의 배포 권한을 새로 만들지 않는다.

구현 결과의 필수 제출물:

1. 파일별 최종 변경 요약과 핵심 규칙/저장/입력 보존 근거.
2. 업데이트한 9축 영향도, 카드 의미 검수 기록, 실제 실행한 테스트/빌드 결과.
3. 동일 상태 기준 전후 캡처. 실제 캠페인과 fixture를 구분.
4. 미확인 항목과 판단 근거. “테스트는 통과했지만 이 동작은 수동 미확인”을 숨기지 않음.

사용자가 해당 구현 세션에 GitHub 게시를 맡긴 경우, 원격/인증 계정을 확인하고 작업 브랜치 PR/격리 프리뷰까지 진행한다. 기존 `.github/pull_request_template.md`의 `IMPACT_ANALYSIS_REQUIRED` 및 필수 영향도 체크 10개를 유지한다. `main` 직접 push/merge와 원래 공개 게임 교체는 별도 지시 범위다.

현재 Pages workflow는 `codex/**` 브랜치 push 시 **main으로 만든 프로덕션 루트 + 별도 브랜치 프리뷰**를 배포한다. 게시 시 최신 workflow를 다시 읽고 경로/부작용을 확인한다. 브랜치명이 같다면 예상 프리뷰 경로는 `/9-baseball/previews/codex-original-ui-refinement/`이지만, 실제 배포 성공과 접속 확인 전에는 완성된 링크로 보고하지 않는다. `VITE_BASE`는 해당 프리뷰 경로에 맞춰 빌드한다.

PR을 만들면 Codex의 PR 첨부 기능으로 해당 작업에 연결한다. 사용자 커뮤니티 대화의 개인 이름·프로필·원본 채팅 스크린샷을 공개 PR에 옮기지 않는다. 피드백은 이 문서처럼 요지로 전달한다.
