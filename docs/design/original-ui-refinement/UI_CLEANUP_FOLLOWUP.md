# 후속 지시 — 전투 화면의 반복 안내 정리

> 후속 방향 변경: 사용자가 더 과감한 정보 재설계를 요청했다. 두 배너 정리는 [새 전투 정보 설계 지시서](../commercial-battle-information-v2/DESIGN_BRIEF.md)에 흡수됐다. 충돌하는 표시 방식은 새 문서를 따른다. 아래 내용은 이전의 작은 정리안으로 보존한다.

2026-10-13 · 1A/2A/3A/4A 적용 이후 사용자 피드백

사용자는 우상단 `▸ 낮게 떨어뜨린다`와 좌상단 `낮은 싱커형 · 레드 러시`를 첨부하며 이제 필요하지 않은 것 같다고 말했다. 이전 요청에 따라 이 세션은 게임 구현 대신 후속 구현 지시만 작성한다.

## 구현 범위

1. **우상단 문장형 투구 경향 배너를 제거한다.** `BallparkBattle.jsx`의 `.bp-tell` / `data-testid="bp-tell"` 렌더링을 없앤다. 싱커 문구 한 개만 예외 처리하지 말고 같은 위치에 나오는 바깥쪽·몸쪽·반대편 등 문구에도 동일하게 적용한다. 해당 배너만 쓰는 CSS를 참조 확인 후 정리한다.
2. **좌상단 유형 접두사를 제거하고 투수명은 남긴다.** `.bp-pitcher-title-name` 안의 `.bp-ptype`와 구분점 ` · `을 제거한다. `.bp-pname`의 `레드 러시` 등 투수명은 HP 패널에서 간단한 제목으로 유지한다. 접두사 제거 후 불필요한 이름 왼쪽 여백도 확인한다. 이는 투수명까지 없애라는 의미로 확대하지 않은 구현 기본안이다.
3. **빈 배너 자리에 다른 UI를 추가하지 않는다.** 도움말 버튼·팝업·새 상태 줄로 대체하거나 배우/존 좌표를 옮기지 않는다.
4. **첫 전투 가이드의 끊어진 연결을 정리한다.** `BallparkCoach.jsx`의 `COACH_STEPS` 중 `.bp-tell`을 가리키는 `투수 속마음` 단계만 제거한다. 기존 9존 설명은 유지하고 가이드 진행 수가 실제 단계 수와 맞는지 확인한다. 가이드 저장 키를 바꾸거나 기존 사용자에게 가이드를 다시 띄우지 않는다.

## 유지할 정보와 동작

- 투수명, HP 막대/숫자, 흔들림 및 활성 효과, 현재 기믹의 숫자·제약·규칙 상세.
- 9존의 공개 분포·읽기 단계·볼 정보, 카드 효과·조건·경고, 에너지·기세·B/S/O·주자.
- 기존 하단 코치 안내와 투수 대사. 이번 사용자 피드백은 이 두 UI의 제거까지 지시하지 않았다.
- 엔진의 intent·archetype 데이터와 실제 확률. 유형은 지도/도감 등 기존 참조처에 그대로 남긴다.
- `intentLines()`는 하단 코치도 사용하므로 함수 전체를 삭제하지 않는다. `whisper` 정리는 다른 참조가 없는지 확인한 뒤 선택한다.
- 카드 선택·지원·스와이프·수동 상세 및 저장 계약.

## 영향도 분석 후 구현

UI/레이아웃, 첫 전투 가이드, 모바일/PC 표시, 관련 테스트에는 영향이 있다. 엔진·밸런스·저장·입력·스크롤·진행 흐름은 변경 대상이 아니다. 구현자는 최신 main과 현재 diff를 먼저 확인하고 기존 AGENTS.md의 9축 영향도 분석을 기록한다. 과거 1A~4A를 다시 구현하거나 실험 브랜치를 합치지 않는다.

## 검수와 제출

- 모바일 375×667 및 390×844와 PC 세로 프레임에서 두 반복 표시가 사라지고 투수명·HP·기믹·9존이 정상인지 확인한다. 새로운 빈 줄/빈 박스가 남지 않아야 한다.
- 첫 방문 상태에서 가이드가 존재하지 않는 요소를 안내하지 않고, 모든 남은 단계를 마칠 수 있어야 한다. 실제 사용자 세이브/가이드 키를 삭제하지 말고 격리한 테스트 상태를 사용한다.
- 변경된 표시 계약에 필요한 테스트만 수정하고 코치/확률/착탄 전 동결 테스트를 약화하지 않는다. 관련 테스트와 저장소 필수 검사 결과를 구분하여 보고한다.
- 전후 실제 화면 캡처로 제거 범위와 정보 보존을 보여 준다. 이 문서는 구현·검증·배포가 완료됐다는 보고가 아니다.
- 기본 제출 범위는 로컬 구현과 검증이다. 별도 게시 요청 없이 GitHub push·PR 생성·main 병합·배포하지 않는다.
