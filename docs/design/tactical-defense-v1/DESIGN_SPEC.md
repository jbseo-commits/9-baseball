# 9ZONE 다음 설계 — 한 번의 스윙이 다음 타석을 바꾼다

2026-10-14 · **게임플레이 실험 지시서 / 구현 전 / 본편 교체안 확정 전**

## 1. 제안의 중심

**이번 타격 작전을 보고 수비가 이동한다. 다음 타자는 그 수비를 이용하거나 다시 바꾼다.**

9존에서 지금 공을 맞힐 위치와 카드를 고를 때, 다음 타석에 남길 수비 상태까지 함께 판단하게 만든다. 현재 카드의 강함과 다음 타자의 기회를 같은 선택 안에서 교환한다. 별도의 수비 이동 버튼이나 새 자원 게이지는 추가하지 않는다.

기억에 남길 경험은 세 가지다.

- 정타: 지금 가장 유력한 존을 칠지, 다음 타자의 장타가 불리하지 않도록 수비를 조정할 존을 칠지 고민한다.
- 연결: 주자를 살리며 수비를 조금씩 바꾸고, 주자와 후속 카드가 준비됐을 때 빈 공간의 이득을 회수한다.
- 희생: 아웃을 지불해 수비를 급격히 당긴 뒤 다음 타자에게 기회를 준다. 영구 아웃 비용 때문에 실제로 가치가 있는지는 실험으로 판정한다.

**새로운 부분은 ‘타석을 넘어 지속되는 공개 수비 상태가 다음 행동의 실제 결과를 바꾸는 것’이다.** 기존 정타 보너스·CONNECT·주자 진루·번트에 새 이름만 붙이는 작업은 이 지시서의 완료가 아니다.

이 규칙은 현실 야구의 정밀 수비 시뮬레이션이 아닌, 야구 덱빌딩을 위한 명시적인 추상 규칙이다. 세계 최초·혁신·재미·상업적 성공이 검증됐다는 의미는 아니다. 플레이어의 선택이 실제로 달라지는지부터 검증한다.

## 5. A의 상태와 적용 시점

수비 깊이는 **전진(0) / 기본(1) / 후퇴(2)** 세 상태만 둔다. 좌우 방향·9개 수비 구역·AI 학습·숨겨진 적응 수치는 첫 실험에 넣지 않는다.

```text
전진 0  ←→  기본 1  ←→  후퇴 2
한 타석 동안 현재 수비는 고정
결과 공개 → 다음 수비 예약 → 다음 타자 진입 때 적용
```

- 실험의 일반 시작은 기본(1). 별도 진단 사례에서는 0/2를 명시적으로 설정한다.
- `depth`는 이번 타석의 공개 상태, `nextDepth`는 공개된 결과로 예약한 다음 타석 상태다.
- 이번 타석 결과의 피해/진루는 **이번 depth**로 계산한다. 그 타격이 만든 다음 수비를 소급 적용하지 않는다.
- 결과가 공개되면 다음 수비와 이유를 표시한다. 실제 수비수 이동은 기존 ‘다음 타자’ 입력에 맞춰 표현한다. 새로운 다음 수비 확인 버튼은 만들지 않는다.
- 파울/볼/같은 타석 다음 공/준비 실행은 수비를 바꾸지 않는다. 장면 재렌더·상세 열기·가로 회전·복원도 바꾸지 않는다.
- 새 투수 경기는 기본(1)으로 초기화한다. C를 켠 실험의 새 런 첫 전투만 지정 초기 상태를 사용한다.

## 6. ‘타격 작전 성향’과 타구 결과를 구분한다

수비는 **공개된 메인 카드의 작전 성향과 성공한 타격**에 반응한다. 성향은 실제 랜덤 타구 궤도와 다른 게임 규칙이다. 장타 작전을 썼어도 실제 결과는 단타일 수 있다.

원래 `r.label`, `r.bases`, 타구 종류 RNG, 그 종류를 참조하는 기존 카드/유물 효과는 바꾸지 않는다. 예컨대 기존 ‘땅볼’ 결과를 임의로 ‘뜬공’으로 고쳐 새 규칙을 맞추지 않는다. 표시에는 `장타 경계로 다음 수비 후퇴`처럼 **수비가 작전을 경계하는 이유**를 쓴다.

첫 실험 지원 카드는 다음 **12종**으로 제한한다. 강화해도 성향은 같고 원래 강화 효과는 유지한다.

| 카드 kind | 작전 성향 | 수비 반응 분류 |
|---|---|---|
| place, strike | 정타 | 실제 적중 코스의 높이에 반응 |
| tableSetter, rally | 진루 | 한 단계 전진 |
| slug, finisher | 장타 | 한 단계 후퇴 |
| bunt, squeeze | 희생 | 조건을 충족한 성공 희생이면 즉시 전진 |
| setup, watch, scout, flow | 준비 | 자체 반응 없음 |

이 메타데이터를 기존 role의 문자열만 보고 추측하지 않는다. `strike`의 역할은 범위지만 실험 성향은 정타다. `finisher`의 이름만 보고 진루로 추정하지 않는다.

기본 스윙 BASIC과 목록 밖 카드는 **공간 효과 없음 / 수비 이동 없음**이다. 진단 경기에는 목록 밖 카드·보상·상점·유물을 새로 유입하지 않는다. 전체 151종 확장은 이 실험 결과를 본 뒤 별도 감사로 한다.

## 7. A의 다음 수비 전이표

일반 공격의 발동 조건은 `hit` + **메인 커버 직접 적중**이다. 지원만 맞은 `assistOnly`에서는 메인 성향 효과와 이동을 발동하지 않는다. 지원 카드가 여러 장이어도 이동은 한 번만 발생한다.

| 성공한 메인 작전 | 다음 수비 |
|---|---|
| 정타 · 실제 공이 높은 행(존 0/1/2) | min(2, depth+1) |
| 정타 · 실제 공이 중간 행(존 3/4/5) | depth 유지 |
| 정타 · 실제 공이 낮은 행(존 6/7/8) | max(0, depth−1) |
| 진루 작전 | max(0, depth−1) |
| 장타 작전 | min(2, depth+1) |
| 유효한 성공 희생 | 0으로 즉시 이동 |
| 나머지 | depth 유지 |

**정타 전이는 노림 anchor가 아니라 실제 공개된 공의 높이**다. 세로 3존을 덮는 카드가 같은 커버를 유지한 채 공짜로 anchor만 바꿔 미래 수비를 조종하는 오류를 막는다. 이것도 새로운 추상 규칙이며 현실의 타구 궤도 법칙이라고 설명하지 않는다.

유효한 성공 희생 조건:

1. 실제 판정이 sacrifice다.
2. 원래 주자가 적어도 한 명 있었다.
3. 실제로 그 주자가 진루/홈인했다.
4. 희생 후 아웃이 3 미만이다.

빈 베이스 번트, 세 번째 아웃, 번트 파울, 번트 삼진에는 수비 유인이 없다. 기존 번트 실행 가능/불가 규칙 자체를 몰래 바꾸지 않는다. 성공 희생은 후퇴(2)→전진(0)으로 바로 바꾸지만 일반 진루 성공은 2→1이다. 두 행동의 기회비용 차이가 핵심이다.

홈런도 성공한 메인 작전의 수비 반응은 적용할 수 있다. 다만 그 공의 공간 효과에는 면역이다. 이미 강판/경기 종료면 다음 수비를 적용할 다음 타석이 없음을 표시하고 새 입력을 만들지 않는다.

## 8. A의 공간 효과 — 첫 실험 후보 수치

**+8 / −4 / 기존 주자 +1루는 미검증 후보값이다. 본편 밸런스 확정값이 아니다.** 최초 비교에서는 고정하고, 변경하면 실험 버전과 변경 이유를 남긴다.

| 현재 수비 | 정타 작전 직접 안타 | 진루 작전 직접 안타 | 장타 작전 직접 안타 |
|---|---|---|---|
| 전진(0) | 기존 효과만 | 최종 HP 피해 −4, 최소 1 | 비홈런 최종 HP 피해 +8 |
| 기본(1) | 기존 효과만 | 기존 효과만 | 기존 효과만 |
| 후퇴(2) | 기존 효과만 | 비홈런에서 **기존 주자만** 추가 1루 | 비홈런 최종 HP 피해 −4, 최소 1 |

- 모든 공간 효과는 메인 직접 안타에서만 발동한다. 메인 미적중/지원 전용 안타/희생/파울/아웃/볼/볼넷에는 없다.
- **홈런은 모든 공간 효과 제외**다. 홈런 주자에게 또 +1루를 주거나 공간 피해를 중복 가산하지 않는다. 원래 홈런은 그대로다.
- HP 계산: 기존 배율·정타·유물·주자·카드 효과를 모두 계산한 최종 피해를 D0라 할 때, 적용 대상 직접 안타의 피해는 `max(1, D0 + 공간 가감)`이다.
- 이 계산을 **HP 차감/국면/HP0 승패 확정 전의 동일한 판정 과정**에서 수행한다. 기존 판정으로 먼저 승리시킨 뒤 −4 때문에 투수를 되살리거나 피해를 두 번 적용하면 안 된다.
- 현재 depth로 가감하고 다음 depth를 사용하지 않는다. 결과 기록에 D0, 공간 가감, 최종 피해를 구분한다.
- 추가 1루는 원래 타격의 진루·준비·성장 등 원래 규칙에 더하되 기존 주자만 대상이다. 새 타자는 추가 대상이 아니다. 이미 홈인한 주자를 또 득점시키지 않는다.
- 추가 진루에 따른 실제 득점은 기존 흔들림 계산에 한 번 반영된다. 그 공의 기존 주자 피해 압박은 투구 전 주자 수를 사용한다.
- 수비는 투구 분포, 미리 생성된 공, 커버, 파울 확률, 안타 보장을 바꾸지 않는다. 실제 수비 아웃/병살 시뮬레이션을 추가하지 않는다.

## 9. 세 가지 플레이의 차이와 아직 보장하지 못한 것

### 정타 중심

현재 공의 적중 가치와 미래 수비 조정을 함께 읽는다. 후퇴 수비에서 다음 장타 카드가 준비되어 있다면, 지금 높은 확률의 상단을 칠지 낮은 행을 노려 수비를 기본으로 돌릴지 갈린다.

단, 낮은 확률의 존을 고르는 것이 실제로 더 합리적인지는 미검증이다. 기존 정타 보너스 때문에 항상 최고 확률 존을 고른다면 **정타 조정 가설 실패**로 기록한다. 수비 이동 화살표만 달라지는 것으로 성공 판정하지 않는다.

### 연결 중심

후퇴 수비의 기존 주자 추가 진루를 이용하고, 진루 작전이 만든 기본/전진 상태를 후속 장타로 활용한다. 주자가 없을 때와 있을 때의 카드 가치가 달라진다.

진루 카드만 채워 성공할수록 전진 페널티에 갇히게 만들지 않는다. 비교용 덱에도 장타 후속 카드가 있어야 한다. 그렇다고 모든 덱이 ‘각 성향 한 장씩 들고 번갈아 사용’하는 같은 정답으로 수렴하면 새 코어는 실패다.

### 희생 중심

후퇴 수비+주자+후속 장타가 있을 때, 두 번의 진루 공격 대신 아웃을 지불해 즉시 전진을 만든다. 다음 타자의 기회를 위해 지금의 더 큰 피해/새 주자 출루 기회를 포기한다.

A에서는 **희소한 작전 후보**로 평가한다. 런 전체에 누적되는 아웃 때문에 희생이 여전히 열위일 수 있다. ‘완성된 희생 덱을 만들었다’거나 ‘첫 세 공에 반드시 희생의 고유성이 드러난다’고 약속하지 않는다. 기본 수비에서 일반 진루와 희생은 모두 전진이 되므로 특별한 속도 차이가 없다.

## 10. B — 희생 아웃 경제의 별도 후보

A에서 수비 유인은 이해되지만 영구 아웃 때문에 희생을 쓰지 않는다는 관측이 있을 때만 B를 비교한다.

> 유효한 성공 희생은 이번 경기 아웃을 그대로 올린다. 투수 강판에 성공하면 그 희생 아웃만 다음 경기로 이월하지 않는다.

- B는 아웃 규칙 변경이다. 단순 UI 개선으로 분류하지 않는다.
- A의 유효한 희생 조건을 모두 만족한 횟수 T만 기록한다. 빈 베이스/세 번째 아웃/파울 삼진은 해당하지 않는다.
- 해당 투수 강판으로 다음 경기로 갈 때 이월 아웃은 `clamp(이번 경기 총 아웃−T, 0, 2)`다. 경기 시작 전 이미 있던 아웃은 T에 포함하지 않는다.
- 경기 중에는 총 아웃을 줄이지 않는다. HP가 남은 상태에서 3아웃이면 그대로 패배한다. HP0와 3아웃이 동시에 발생할 때의 현행 엔진 우선순위는 별도 변경하지 않고 회귀로 고정한다.
- 번트 파울 삼진과 일반 아웃은 기존처럼 이월한다. 다음 안타 즉시 환급·매 투구 환급·전투 포기 환급은 없다.
- A/B를 같은 수비·손패·공·HP로 비교한다. ‘B의 아웃 보상’과 ‘A의 수비 변화’가 각각 어떤 선택을 바꿨는지 나눠 기록한다.
- B도 실패하면 희생을 독립된 덱 정체성으로 밀지 않는다. 성공률/피해를 계속 올려 의무 카드로 만드는 방식을 기본 해법으로 삼지 않는다.

## 11. C — 시작 상황이 플레이를 바꾸는 별도 후보

현재 시작 팩은 유지한 비교와 구별한다. 팩 카드 교체나 첫 손패 보장 자체는 이미 있는 기능이다.

C의 후보는 **수비 깊이 3종 × 주자 없음/1루 주자 있음 = 6개 공개 시작 상황**이다. 새 런의 첫 전투에만 적용한다. 그때의 아웃은 원래 새 런과 같이 0이고 추가 팝업/선택 화면 없이 경기장에 바로 보인다. 이후 경기의 누적 아웃을 0으로 만들거나 주자를 다시 주입하지 않는다.

- 시드와 경기 식별자의 별도 결정적 hash로 상황을 정한다. 기존 pitchSeed/deck RNG를 소비하거나 현재 공을 재추첨하지 않는다.
- 같은 시드/상황에서는 어떤 시작 팩을 골라도 초기 수비·주자가 같다. 팩별 유리한 상황을 몰래 골라주지 않는다.
- 기존 1루 주자는 현재 타자와 다른 합법적인 LINEUP 선수 ID를 사용하고 중복 출루/타석 순서 충돌을 검수한다.
- ‘찬스 상황에서 시작 · 1루 주자’처럼 실제 초기 조건임을 전광판에 짧게 표시한다. 플레이어가 얻지 않은 안타/득점 통계를 임의로 올리지 않는다.
- 기존 본편에서 모든 경기가 빈 베이스로 시작하는 규칙과 다르다. 실험 버전에서만 적용하고 이전 세이브에 소급하지 않는다.
- 여섯 상황을 자연 시작 평가에서 균형 있게 표집한다. 서로 다른 상황만 비교해 덱 차이가 입증됐다고 주장하지 않는다.
- 진단 손패 고정으로 새 규칙을 보여주는 시험과 실제 셔플로 첫 3~5공의 선택을 보는 시험을 분리한다. 자세한 표는 PLAYTEST.md를 따른다.

## 12. 경기장 표현 — 실제 규칙의 인과를 보이게 한다

원래 세로 구도·플레이트·마운드·타자·투수·카드 그림을 유지한다. 경기장을 전술 보드 전체로 교체하거나 수비용 두 번째 9칸 보드를 만들지 않는다.

- 9존은 계속 **투구 코스**다. 수비는 경기장 안의 앞/뒤 위치다. 투구 열지도의 색을 수비 유불리 색으로 덮지 않는다.
- 대표 수비수 3명의 실루엣/자리로 깊이를 읽는다. 세 명이 전체 수비 인원이라는 뜻은 아니다. 이동 폭이 모바일에서 구분되어야 한다.
- 전진/기본/후퇴의 이름과 현재 적용 효과를 한 고정 슬롯에 표시한다. 작은 움직임만 보고 규칙을 추측하게 하지 않는다.
- 선택 요약에는 `정타 적중 높이에 따라 다음 수비 조정`, `진루 적중→한 단계 전진`, `유효 희생→즉시 전진`처럼 **조건부 반응**을 표시한다.
- 예측은 공개 커버와 읽기 수준만 이용한다. 세로 커버가 여러 행이면 다음 수비를 하나로 확정 표시하지 않는다. 필요하면 정보 보기에 행별 전이표를 제공한다.
- 현재 수비의 실제 +8/−4/주자 추가 진루는 적용 대상 카드에 분명히 표시한다. ‘유리/불리’ 아이콘 하나 뒤에 숫자를 숨기지 않는다.
- 결과에서 원래 실제 타구/피해/주자 움직임을 먼저 보인다. 이어 `장타 경계→다음 수비 후퇴` 등 이유와 다음 상태를 같은 결과 영역에서 짧게 보여준다.
- 다음 타자 진입 시 수비수 이동을 약 180~300ms의 짧은 후보 연출로 표현한다. 별도 확인 탭이나 연출 대기 버튼을 추가하지 않는다. reduced-motion은 즉시 자리/텍스트 갱신으로 대체한다.
- 카드를 고를 때 경기장/9존/손패/실행 hitbox는 움직이지 않는다. 일반 전투의 세로 스크롤은 없다. 자동 정보 팝업도 없다.

### 에셋 범위

기존 배우·구장·카드 이미지·공/VFX는 재사용한다. 조사에서 전용 수비수 런타임 에셋의 존재는 확인하지 못했다. 필요한 신규 에셋은 **대표 수비수의 식별 가능한 작은 실루엣과 이동/정지 포즈**로 한정한다.

첫 규칙 검증은 비인물 위치 마커로 할 수 있다. 그것을 상업 아트 완성본으로 보고하지 않는다. 인물 에셋을 넣을 때는 기존 AGENTS의 축소 판독·발 접지·포즈·명암·환경 통합 기준으로 검수한다. 저품질 임시 인물이나 이미지 한 장의 회전/이동만으로 애니메이션 완성을 주장하지 않는다. 이 문서 작성 중에는 에셋을 생성하지 않는다.

## 13. 상태/저장/구현 경계

첫 구현은 localhost 개발 전용 분리 실험이다. 동일한 원래 전투 렌더러를 사용하되 본편 진입·실제 사용자 세이브에 연결하지 않는다.

- 실험 진입은 DEV에서만 열리는 지정 query/도구로 제공한다. 예: `?experiment=defense-v1`. production에서 임의 query로 신규 규칙이 켜지면 안 된다.
- 본편 `9zone-v10-run` 및 기존 가이드/설정 키를 읽어 변환·삭제·덮어쓰지 않는다. 첫 실험은 메모리 상태로 충분하다. 필요할 때만 실험 전용 sessionStorage envelope/키를 둔다.
- 초기 실험의 `depth/nextDepth`, A/B/C 버전, 후보 파라미터, B의 T, 진단/자연 시작 여부를 명시적인 실험 상태로 관리한다. UI class/DOM 위치를 규칙의 원천으로 삼지 않는다.
- 기존 engine을 복사해 별도 거대 엔진을 만들지 않는다. 필요한 판정 hook/adapter를 좁게 두고 flag OFF의 기존 상태/결과가 유지되는 회귀를 만든다.
- HP/주자 변화는 승패/보상 확정 전 동일 과정에서 계산한다. 기존 action 실행 후 HP만 사후 덧칠하는 adapter는 금지한다.
- 엔진 결과 데이터에는 depthBefore/nextDepth, 반응 원인, 공간 피해/진루를 기록한다. 화면은 그 기록을 사용한다.
- 새 규칙 때문에 본편 SAVE_KEY/schema를 바꾸거나 ‘손상 시 초기화’로 처리하지 않는다. 상용 통합의 스키마 이행은 실험 통과 후 별도 설계다.
- 수비 시프트는 현재 공의 분포·pending zone/roll/powerRoll을 변경하지 않는다. 새 규칙에 추가 RNG는 없다.
- 착탄 전에는 이전 HP/아웃/주자/기세/흔들림/수비가 보인다. 새 nextDepth·공간 가감·주자 추가 이동·KO는 기존 결과 공개 시점 뒤에만 보인다. 정보 보기/aria/VFX에도 같은 경계를 적용한다.

## 15. 구현 및 검수 순서

1. 최신 checkout/diff와 AGENTS를 확인하고 이 문서의 실제 기존 기능 근거를 대조한다.
2. A의 순수 상태 전이·공간 효과·판정 시점/예외를 먼저 검수 가능한 단위로 만든다.
3. 원래 전투 렌더러에 현재 수비/다음 상태의 인과를 연결한다. 새 화면 장식만으로 완료 처리하지 않는다.
4. PLAYTEST.md의 진단 사례로 규칙을 검증하고, 같은 사례의 A OFF/ON을 비교한다.
5. 자연 셔플/첫 3~5공에서 선택·조작 부담·동일 정답 여부를 관찰한다.
6. A 결과와 실패 사례를 제출한다. B/C를 켤 근거가 있는지 나눠 판단한다.
7. 사람 플레이에서 의미 있는 차이가 확인된 뒤 전체 카드·투수·보상·아웃 경제·세이브 이행·아트 완성을 별도 범위로 확장한다.

테스트 통과는 규칙 동작의 근거다. 재미나 상업성을 입증하지 않는다. 구현 결과가 시각적으로만 다르고 고르는 행동이 같다면 실패 사례로 제출한다.

## 16. 제출물과 중단 기준

- 현행과 A의 동일 조건 비교 영상/캡처, 실험 버전/파라미터/시드/손패/공개 수비·주자 조건.
- 각 사례에서 플레이어가 지금 이득과 다음 타석 이득 중 무엇을 골랐는지 설명한 기록.
- 정타 조정·연결 회수·희생 급변의 실제 선택 변화/포기 사례. 안 나온 경우 그대로 기록.
- 규칙/공개 정보/입력/저장/전체 회귀·build/smoke 결과, 실기기 미확인 목록.
- 공간 효과 때문에 변한 최종 피해·주자·국면·승패의 계산 근거.

다음이면 확장하지 않는다: 원래 최고 확률 존만 계속 선택함, 카드 이름이 달라도 같은 두 성향 자동 교대가 항상 정답, 희생이 항상 열위/필수, 설명을 읽느라 원래 카드 조작이 느려짐, 수비 효과를 모르고 결과를 버그로 이해함.

## 17. 자료와 다음 세션 전달

현재 사실은 `src/duel/engine.js`(START_PACKS·previewV10Stack·playV10Action·advanceV10Batter·claimV10Reward), `cards.js`, `cards-v16.js`, `pitcher-hp.js`, `App.jsx`, `v10-storage.js`를 읽어 확인했다. 실행 검증은 이 문서 작성에서 하지 않았다.

비교 설계 참고: [GDC 2019 — Into the Breach Design Postmortem](https://www.gdcvault.com/play/1026333/-Into-the-Breach-Design)의 공개 세션 소개는 초기 설계부터 잘라낸 콘텐츠·반복·최종 밸런스에 이르는 검토 과정을 다룬다. 본 문서의 수비 규칙은 9ZONE을 위한 제안이며 해당 게임의 규칙을 검증/복제했다는 뜻이 아니다. 소개 페이지만 확인했으며 영상을 시청했다고 주장하지 않는다.

다음 세션에는 [진단·플레이 검수표](PLAYTEST.md)와 [실행 프롬프트](IMPLEMENT_THIS.md)를 함께 전달한다.
