# C08 — 전체 적용 범위와 출시 전환

담당: Codex 통합자. 선행 C07 G3. **대표 전투 프리뷰와 전체 상업 아트 완료를 구분하는 최종 단계**다.

C08은 C07 뒤에 착수하는 발주·통합 관리 티켓이다. 아래 R1–R6과 A03이 끝나야 C08의 G4를 완료한다. 후속 작업 완료를 C08의 착수 조건으로 두지 않는다. 각 R의 편집은 별도 인수 기록으로 하나씩 진행한다.

## 전체 확장은 아래 작은 작업으로 순차 발주

| 후속 단위 | 편집 담당 / 파일 범위 | 입력 | 인수 |
|---|---|---|---|
| R1 카드 한 가족씩 | Claude, card-art 매핑의 지정 family + 새 자산. 해당 기간 통합자 소유권 인계 | A03의 검수된 카드 묶음 | 전투·보상·도감에서 같은 id/그림, 강화·긴 이름·축소 가독성 |
| R2 투수 한 명씩 | Claude, pitcher-visuals의 지정 artId + Scene 매핑. 엔진 수치 제외 | A03의 해당 투수 portrait/전신/동작 | 소개→전투→강판의 같은 인물, 기존 성향/HP 유지 |
| R3 타이틀/시작팩 | Claude, TitleScreen·StartPackPick 관련 전용 스타일 | 확정 palette·현재 승인 아트 | 첫 진입/연습/팩 선택 동작과 스타일 |
| R4 지도/상대소개 | Claude, BallparkMap과 소개 UI의 전용 스타일 | 현재 경로/상대 데이터 | 긴 지도 스크롤·선택·이어하기 |
| R5 보상/시설/이벤트 | Claude, BallparkStop·BallparkEvent의 전용 스타일 | 같은 카드 얼굴/패널 | 선택/건너뛰기/회복·강화·제거 등 기존 동작 |
| R6 도감/엔딩 | Claude, 현재 main의 실제 도감/엔딩 파일을 탐색 후 한 화면씩 지정 | 동일 카드·로스터 목록 | 도감 스크롤/상세와 승패 흐름 |

각 R 티켓을 시작할 때 실제 최신 파일·출력·제외·검증을 WORKLOG에 고정한다. R1/R2의 전체 항목을 한 PR에 몰지 않는다. 전체 로스터 수는 최신 목록으로 산정한다. 사용자 승인 없는 캐릭터 재설계는 하지 않는다.

## 전환 순서

1. 카드/배우/화면 카탈로그를 실제 런 연결과 대조한다. 빠진 부분을 “남은 아트”로 명시한다.
2. 대표 장면 프리뷰만 공개하는 단계면 query 경로를 유지하고 범위를 표시한다. 전체 완성으로 이름 붙이지 않는다.
3. 전체 전환 후보에서는 새 렌더러를 기본으로 바꾸는 변경과 이전 경로 제거를 분리한다. 초기 전환에는 코드로 되돌릴 수 있는 이전 경로를 보존한다. 플레이어용 설정 메뉴를 늘릴 필요는 없다.
4. 실제 사용자 승인 범위가 PR/프리뷰 게시까지이면 그 범위로 진행한다. main 병합·배포는 그 세션의 승인 범위와 저장소 규칙에 따른다. 이번 계획 작성으로 자동 실행하지 않는다.
5. PR에는 문제/새 행동/9축 영향·필수 체크/실제 테스트/화면/한계/프리뷰 SHA를 적는다. API·문서·CI 검사로 대체할 수 없는 실기기 상태를 별도로 표시한다.
6. 실제 배포 후 타이틀→전투→다음 화면, asset base path·캐시·세이브를 확인한다. 게시하지 않았으면 배포 후 확인을 완료라고 쓰지 않는다.
7. 안정화 후 사용되지 않는 전역 CSS·옛 배우 경로를 별도 정리 PR로 제거한다. 스타일 이식 PR에서 무관한 파일을 일괄 삭제하지 않는다.

## 최종 인수 G4

규칙/세이브 유지, 기준 미감, 실제 동작, 전체 대상 자산 연결, 지원 화면·장치, QA 증거, 실제 게시 상태가 모두 일치한다. 롤백은 저장 schema 변경 없이 UI 경로/커밋을 되돌리는 절차로 검증한다.

R1–R6/A03의 마지막 변경 뒤 영향받은 화면·자산·동작 QA를 갱신하고, 최종 통합 HEAD에서 전체 테스트·필수 스모크·production build·용량 검사를 수행한다. 확장 전 C07 기록만으로 G4를 통과시키지 않는다. 그 이후 변경이 없으면 같은 검증을 다시 반복할 필요는 없다.
