# 아트 제작과 납품 계획

현재 자산의 수준은 **새 화풍의 원화·정적 구도 기준**이다. 타자·투수는 각각 1포즈이며, 카드 그림은 3×2 샘플 시트다. 출시 동작·전체 카드·전체 투수는 별도 작업량이다.

## A01 — 시각 기준과 배포 입력 정리

담당: Codex 아트 총괄. 선행: C00. 납품을 받은 C02가 Scene에 연결한다.

| 자산 | 동봉 파일 | 납품/검수 |
|---|---|---|
| 구장 | `reference/art/stadium-wide.png` | 선정본 고정, 홈/마운드 좌표. 1차는 단일 배경; 효과가 입증될 때 근·중·원경 분리 |
| 우타자 | `batter-catcher.png` | 원본 투명 PNG, 그립·발·anchor. 현재 1포즈임을 표기 |
| 투수 | `pitcher-home.png` | 원본 투명 PNG, 오른손 공/왼손 글러브, anchor. 특정 기존 로스터로 자동 확정하지 않음 |
| 카드 | `cards.png` | 3×2 원화 참조. 비용·카드명·효과는 별도 UI |
| 디자인 토큰 | 목업 style 참조 | 아래 팔레트·서체·프레임·아이콘 크기 기준 |

팔레트 시작값: ink `#12272b`, deep `#101f24`, paper `#f5edda`, orange `#f87943`, teal `#8ad1c1`, muted `#afc4b9`. 가독성을 위한 대비 조정은 허용하되 새 화풍·장식 체계로 재디자인하지 않는다. 한글 본문은 본편 자체 호스팅 Noto Sans KR을 재사용한다. 새 웹폰트 다운로드를 필수 의존성으로 늘리지 않는다.

### 실제 상대에 연결하는 기준

A01은 `actor-coverage.json`도 납품한다. 각 항목에 `existingArtId / sourceFile / identityEvidence / approvalStatus / staticReady / motionReady`를 기록한다. 목업의 화면 이름만 보고 샘플 그림을 기존 로스터에 자동 연결하지 않는다. 기존 상대와 외형이 다르면 해당 상대의 정체성을 유지한 같은 화풍의 원화를 먼저 준비한다.

고정 시각 fixture에서는 선정 그림을 `sampleActor`로 사용해 구도·미감을 검토할 수 있다. 실제 런에서는 매핑이 검수된 artId만 새 Scene으로 진입한다. 미지원 상대는 C05의 **기존 전투 전체 UI fallback**으로 표시하고, 같은 샘플 투수를 반복 사용하지 않는다. 이 혼재는 프리뷰의 명시적 한계다. G1 완료에는 실제 상대 최소 한 명의 정적 매핑, G2에는 그 상대의 동작 매핑이 필요하다. 전체 전환 G4에는 출시 대상 로스터의 coverage를 채운다.

원화 합계는 **8,565,812바이트**다. 원본 보존과 배포 최적화는 별개다. 제안 경로 `assets/production-art/battle-vnext/`에서 원본을 관리하고, 기존 `scripts/optimize-runtime-art.py`의 해당 경로 규칙을 통합자가 추가한다. 원본이 match되지 않으면 자동 최적화가 안 되므로 스크립트를 실행했다고 끝내지 않는다.

기존 WebP 파이프라인을 우선 쓴다. 생성 후 재빌드해 실제 dist 파일·alpha·카드 작은 글리프·배우 윤곽을 검사한다. 일러스트 atlas는 셀 비율을 보존한다. 원본 4개를 `public` 폴더에 놓아 빌드 최적화를 우회하지 않는다. 파생본 생성 도구는 manifest와 오래된 파생본도 갱신하므로 통합자만 실행하고 diff를 검토한다.

## A02 — 대표 타자·투수 한 쌍의 실제 동작

선행: **C05의 가로/세로 카메라·UI 구도 G1 통과**. 그 전에 전체 로스터 모션을 대량 제작하지 않는다. 담당: 아트 제작, Codex 시각 검수. C06이 엔진 이벤트에 연결한다.

| 배우 | 필요한 동작 | 반드시 확인할 접점 |
|---|---|---|
| 타자 | 준비, 로드, 스윙 시작, 접촉, 팔로스루, 회복, 지켜보기·헛스윙 분기 | 왼발 선행/오른발 후행, 오른손 위/왼손 아래, 배트 궤적, 공 접촉, 몸통 회전 |
| 투수 | 세트, 코일/다리 들기, 스트라이드, 릴리스, 팔로스루, 회복 | 축발·딛는 발, 오른손 릴리스, 왼손 글러브, 마운드 접지 |
| 결과 | 정확 읽기, 일반 안타, 범위 적중, 근접 실패, 파울, 볼/루킹, 홈런, 강판 | 실제 판정과 사운드/VFX 강도·시간 일치 |

키포즈를 먼저 한 프레임씩 검수하고 그 사이를 제작한다. 프레임 수/fps/atlas 규격은 대상 배우의 저장소 제작 계약을 따른다. 정지 원화의 확대·기울임·흔들림만으로 완성 모션이라고 하지 않는다. 신규 투수 제작에 해당하면 저장소 `docs/art/PITCHER_CHAT_FIRST_CACHE_WORKFLOW.md` 등 승인·원본/출처 계약을 적용한다. 기존 목업 방향 채택이 새 캐릭터 로스터 편입·완성 모션 검수를 자동 대체하지 않는다.

납품 묶음:

1. 편집 가능한 원본과 프레임별 투명 PNG.
2. atlas와 `cellSize/frameCount/fps/sequence` metadata.
3. 프레임별 pivot, 발 접점, `release/contact/end` 이벤트. 배우 artId와 방향 명시.
4. 원본/파생본 해시·제작/참조 출처·권리/승인 상태.
5. 가로/세로 실제 크기 재생 영상, 정지 키포즈 비교, 투구/타격 느린 재생.

일반 적중보다 정확 읽기를 강하게 연출하되 모든 결과를 홈런처럼 만들지 않는다. ‘한 칸 차이’는 실제 근접 판정에만, HP 감소는 실제 값만 표시한다. 오디오 muted/reduced-motion 경로도 C06 인수에 포함한다.

## A03 — 전체 카탈로그로 확장

선행: 대표 동작과 실기기 G2/G3 통과. 먼저 실제 main의 목록을 자동 수집하고 누락표를 만든다. 개수를 추정해 채우지 않는다.

| 묶음 | 나눌 단위 | 완료 기준 |
|---|---|---|
| 카드 | 시작팩의 첫 손패 → 공용 핵심 → 나머지 가족별 | 151종 각각 id/용도/이미지/상태/작은 화면 검수. 강화는 읽히는 UI 구별 유지 |
| 투수 | 기존 한 명씩, 일반·엘리트·보스 순서 | artId·이름·성향·portrait·전신·모션·강판 표현 연결. 같은 샘플 배우로 모든 상대 대체 금지 |
| 비전투 화면 | 타이틀/시작팩, 지도/상대소개, 보상/시설, 도감/엔딩 | 같은 글꼴·패널·카드·팔레트. 각 화면 실제 입력·스크롤 검수 |

권장 목록 필드: `id / screen / source / runtime / artId-or-cardKind / poseCoverage / status / owner / approvalEvidence / screenshot / unresolved`.

카드 가족별 공통 구도는 사용할 수 있지만, 서로 다른 카드가 같은 그림으로 오인되는지 검사한다. 현재 6셀 그림이 6종 최종 카드에 정확히 대응한다고 가정하지 않는다.

기존 승인된 로스터 디자인은 유지하며 새 스타일로 옮긴다. 캐릭터 변경과 화풍 이식을 한 작업에 섞지 않는다. 누락 자산은 프리뷰 한계로 표시하며 출시 완료 목록에서 제외한다.

## 출처와 사용 범위

`reference/art/manifest.json`은 선정 원화의 생성 출처, `reference/NOTICE.md`는 현재 동봉 자료의 권리·포함 범위를 기록한다. **현재 선정 파일과 해시는 PACKAGE-MANIFEST.json을 우선**한다. 실제 타석 출처는 `reference/baseball-references.md`에 있다. MLB 도면과 외부 사진은 구도 참고이며 이 패키지의 런타임 이미지로 배포하지 않는다. 본편 폰트의 라이선스를 유지한다.
