# 9ZONE HOMEBOUND — 가로 전투 목업

2026-10-27 · 기존 별도 목업의 개발 기록

이 문서는 목업 제작 당시의 기록이다. 현재 동봉 폴더는 실행 앱이 아니라 구현 참조 패키지다. 아래 엔진 연결·검증 기록은 당시 목업에 대한 것이며 본편 이식 완료를 뜻하지 않는다. 현재 작업은 [구현 계획](../PLAN.md)과 [Claude 지시문](../CLAUDE-START.md)을 따른다.

## 가로 화면의 설계

상단은 상대 HP·카운트, 왼쪽 아래는 손패와 그 바로 위의 현재 에너지, 오른쪽은 9존·선택 요약·행동 버튼으로 구성했다. 넓은 가운데 공간은 타자와 투수의 대결에 쓴다. 손패를 별도 화면으로 여는 단계는 없다. 작은 가로 화면에서는 카드 글자를 줄이는 대신 가로 스크롤과 ‘넘겨보기 →’ 표시를 사용한다.

노릴 코스와 카드 조합은 선택 중 계속 바꿀 수 있다. 현재 메인/지원의 커버는 주황 실선/청록 점선, 카드 순서는 작은 숫자, 비용은 ϟ 기호로 구분한다. 결과에서는 선택 지시 대신 실제 도착 코스를 표시하고, 안타 종류·출루·투수 HP 변화를 먼저 보여준다.

## 에셋과 UI: 실제로 나눈 부분

| 요소 | 현재 파일/구현 | 출시 제작에서 이어갈 부분 |
|---|---|---|
| 구장 | `art/stadium-wide.png` — 인물을 제거해 따로 제작한 1672×941 배경 | 근경·중경·원경 분리, 필요 시 낮/밤 변형 |
| 타자·투수 | `art/batter-catcher.png` 포수 시점 우타자 + `art/pitcher-home.png` 홈을 바라보는 투수 정지 포즈 | 인물별 고정 피벗·접점, 준비/투구/타격/후속 동작 프레임 |
| 인물 배치 | `scene.js`가 구장 좌표에 고정하고 카메라를 공통 적용 | 프레임 교체 시 같은 피벗을 유지; 휴대폰과 PC의 크기·위치 검수 |
| 접지 그림자 | 발 접점의 구장 좌표에 고정한 CSS 레이어 | 포즈별 발 위치와 광원에 맞춘 그림자 아트/변형 |
| 카드 그림 | `art/cards.png` — 이전 새 화풍 시안의 3×2 카드 원화 재사용 | 전체 카드군을 기능별 구도·팔레트로 제작하고 작은 크기 검수 |
| 존·텍스트·카드 틀·HP·버튼 | 실제 HTML/CSS/SVG | 기존 React UI에 컴포넌트로 이식; 수치와 문구는 동적 표시 |
| 공·결과 | 간단한 공 이동, 실제 판정 후 도착 존·궤적·문구 | 릴리스/접촉 이벤트와 맞는 공 궤적, 전용 타격 음향·VFX |

**배경과 인물은 실제로 분리되어 있다. 인물의 투구·스윙 애니메이션은 아직 없다.** 원화 한 장을 움직여 완성 모션이라고 부르지 않는다. 이 시안에서 결과가 나와도 인물은 준비 자세를 유지한다. 신규 투수의 최종 로스터·모션 승인 절차를 대신하는 산출물이 아니다.

배경 1672×941 좌표에서 마운드 (832,580), 홈 중심 (815,824), 타자 오른쪽 뒤발 (520,909), 왼쪽 앞발 약 (594,814)을 기준으로 배치했다. 홈 중심 자체에 타자를 세우지 않는다. 가까운 타자 높이 670, 먼 투수 높이 310으로 비율을 고정하고, 화면 크기가 달라져도 구장·인물에 같은 확대/이동을 적용한다. 타자 다리가 손패에 가려져도 발을 UI 기준으로 옮기지 않는다. 투수는 홈을 바라보는 별도 오른손 투수 포즈로 교체했다. 이미지 원본을 코드로 잘라 다시 그리지 않았으며, 타자와 투수 모두 새 단일 투명 PNG를 표시한다. 타자는 포수 뒤에서 투수를 보는 시점의 왼쪽 우타석에 맞춰 다시 제작했다. 왼어깨·왼발이 투수 쪽, 오른어깨·오른발이 포수 쪽이며 저지 앞면 일부가 보인다. 그립은 오른손이 배럴 쪽, 왼손이 노브 쪽이다. 새 원화의 발 접점에 맞춰 피벗과 그림자 위치도 조정했다. 최종 제작에서는 투명 여백·외곽 잔여 픽셀과 장비 실루엣을 정리하고 프레임별 접점을 검수해야 한다.

네 가지 런타임 PNG의 합계는 8,565,812바이트(약 8.17 MiB)다. 배포용 해상도별 WebP/AVIF 및 디코딩·로딩 성능 최적화는 아직 하지 않았다. 현재 선정 원화와 생성 식별자는 `art/manifest.json`에 기록했다.

## 실제 게임과 연결된 범위

본편 main `f3ec4be`에서 복사한 엔진으로 카드 비용·커버·공개 확률·안타 판정·HP·주자·다음 공을 계산한다. 기본 에너지는 2다. 초기 조합은 비용 1 라인드라이브와 비용 1 정타 노림이며, 2 에너지를 사용한다. 스코프와 호크아이를 보유한 읽기 II 검토 시나리오이므로 정확한 공개 분포를 표시한다. 숨은 투구 정답을 UI에서 미리 읽지 않는다.

초기 스윙은 실제 시드 13의 엔진 판정으로 중전안타, 1루 출루, 투수 HP 60 → 50이 된다. 확률·결과를 이미지에 굽지 않았다. 예산 안의 추가 공격 카드는 지원 코스를 고른 뒤 확정하고, 예산을 넘으면 메인으로 교체한다. 준비 카드, 비용 부족 차단, 무료 기본 스윙, 지켜보기와 다음 공 에너지 3도 엔진에 연결했다.

진행은 브라우저 메모리에만 있다. 새로고침하면 초기화하며 운영 게임의 저장 데이터를 읽거나 쓰지 않는다. 전투 이후 보상·승리·패배에서는 목업을 다시 시작한다. 전체 런과 모든 카드 조합을 완성한 버전은 아니다.

## 검증

실제 Chromium 브라우저에서 다음 크기를 촬영하고 검사했다.

- 휴대폰 가로: 667×375, 740×360, 844×390, 932×430
- PC 가로: 1440×900
- 회전 확인용 세로: 390×844

문서 가로 넘침, 카드 하단 잘림, 결과와 카드/실행 버튼 겹침, 오른쪽 결과 문구 넘침이 없었다. 9존·읽기·무료 기본 스윙·지켜보기 버튼은 44px 이상이다. 작은 화면에서는 남은 손패를 가로로 넘긴다.

실제 터치 이벤트로 손패를 넘겨 의도하지 않은 카드 선택이 없음을 확인했다. 에너지·중심/모서리 커버·지원 선택·준비·지켜보기·실제 안타·정확/범위 적중 구분·연속 클릭 차단·화면 회전 시 상태 보존도 확인했다. 결과는 `shots/verification.txt`, 레이아웃 측정은 `shots/layout.json`에 있다.

현재 검증은 Chromium의 뷰포트/터치 에뮬레이션이다. iPhone/Safari와 실기기 노치·홈 인디케이터·발열·성능 검수, 긴 모든 결과 문구, 151종 카드 전면, 읽기 0/I 시각 설계는 후속 범위다. 최소 가로 높이는 360px이며 그보다 낮으면 페이지 스크롤이 필요할 수 있다.

## 실행 및 산출물

이 참조 폴더에는 실행 앱과 엔진 사본이 없다. 본편 작업·실행은 [Claude 시작 지시문](../CLAUDE-START.md)과 [QA 명령](../QA.md)을 따른다.

`shots/desktop.png`, `shots/phone.png`, `shots/result.png`는 실제 브라우저 캡처다. 운영 저장소·기존 세로 목업·GitHub Pages 배포는 변경하지 않았다.

## 배치 수정 검증

`shots/diamond.png`는 실제 게임에서 UI만 숨겨 촬영한 구도 확인 화면이다. 배경에 맞는 발 위치·거리·시선을 검토했다. `shots/scene-verification.txt`는 6개 뷰포트에서 투수 축발과 마운드 좌표 일치, 타자 발의 홈 왼쪽 위치, 인물 원근 비율 유지를 확인한 기록이다. `scene.js`의 랜드마크는 현재 원화 기준이며 다른 배경을 쓸 경우 새로 검수해야 한다.

## 에너지 표시 위치

현재 에너지를 손패 헤더 왼쪽, 첫 카드 바로 위로 옮겼다. 기존 에너지 DOM을 이동해 단일 표시를 유지하며 엔진 값은 그대로 연결된다. 결과 화면에서도 에너지를 숨기지 않는다. 6개 뷰포트에서 카드 위 4~6px 간격, 헤더 겹침 없음, 실제 스윙 후 2→0 갱신을 확인했다. 기록: `shots/energy-verification.txt`.

## 타자 좌우 방향 수정

이전 원화는 왼쪽 우타석에 놓였지만 상체가 좌타로 읽혀 교체했다. 타석 위치뿐 아니라 손의 순서, 앞뒤 어깨, 양발 방향을 함께 검토했다. 독립 원화 검토와 실제 장면 검토에서 우타 자세의 일관성을 확인했다. 새 발 접점에 맞춰 피벗과 그림자를 조정했고, 6개 뷰포트 정렬·캡처 검사를 통과했다. 인물은 여전히 정지 포즈이며 실제 스윙 모션은 아직 없다. 최신 휴대폰 캡처: `shots/phone.png`.

## 실제 타석 참고 수정

MLB 2026 규칙집 Appendix 2와 실제 구장 사진 두 장을 열어 확인했다. 홈 크기, 4×6피트 타석과 6인치 간격의 비례를 참고해 배경을 다시 만들고, 우타자 양발을 타석의 앞뒤 방향에 놓았다. 두 신발 전체가 타석 안에 있는지 실제 장면에서 확인했다. 원화의 배트가 휴대폰 HUD에 가리지 않게 타자 높이를 670으로 조정했다. 배경이 바뀌면서 홈·마운드·그림자·공 이동 시작/도착 위치도 함께 갱신했다. 최종 그림은 규격 도면을 참고한 시안이며 모든 픽셀의 실측 정합을 보증하지 않는다. 출처·관찰·라이선스: `baseball/README.md`.
