## 목표와 현재 판단

목표는 `docs/art/benchmark/target/`의 10장(세로 전투, 가로 전투, 지도, 보상, 덱, 도감, 타이틀, 홈런, 강판, 엔딩)을 실제 게임 화면과 장면 전환에서 재현하는 것이다. **이번 작업의 주 책임은 이미지·캐릭터·애니메이션·VFX 제작**이다. UI의 세부 위치·타이포그래피·상태 연결은 제미나이가 조정할 수 있도록 투명 레이어, 기준 좌표, 타이밍, 매니페스트를 전달한다.

`docs/antigravity/QUEUE.md`의 P1·P2 완료는 기능 연결과 당시 자동 QA의 기록이다. 2026-09-28 `work/qa-v15-title-ending/`에는 전투·지도·보상의 3뷰포트 캡처만 있고, 타이틀·덱·도감·홈런·강판·엔딩의 **목업 1:1 캡처 판정은 없다**. 최신 가로 전투 캡처에서 타자가 목업보다 작고, 카드/버튼/9존의 시각 비중도 다르다. 지도와 보상도 배경은 연결됐으나 목업의 정보 위계와 인물·카드 구도가 다르다. 따라서 기존 `27/27 PASS`와 테스트 통과를 **10개 화면의 목업 일치 판정으로 해석하지 않는다**.

레드 러시는 사용자 결정에 따라 **현행 여성형 정체성을 유지**한다. 목업과의 성별 차이는 결함으로 취급하지 않는다. 현행 전투 투수·도감 초상·강판 컷의 얼굴, 복장, 장비, 장면 크기와 동작 일관성을 기준으로 비파괴 보완 후보를 만든다. 이미 출시된 캐릭터 설정과 런타임 에셋은 화면별 비교와 검토 전까지 보존한다.

## 작업 단위와 품질 게이트

1. **목업 한 장 → 핵심 장면 한 묶음**으로 진행한다. 매 작업 시작 전 `git status --short --branch`, 해당 목업, 실제 캡처, 현행 원본을 확인한다. 다른 세션의 미커밋 파일과 브랜치는 건드리지 않는다.
2. 인물 에셋은 `READY/LOAD/CONTACT` 같은 개별 보기만으로 승인하지 않는다. 같은 크기로 겹쳐 얼굴·헬멧/모자·유니폼·손/글러브·발 기준선·광원을 비교하고 **작은 게임 표시 크기**에서도 확인한다.
3. 애니매틱은 키포즈 타이밍 확인용으로 표기한다. `animation complete`는 실제 게임 속도에서 끊김, 팔/다리 점프, 공 중복, 발 미끄러짐, 타격 접점 이탈이 없을 때만 사용한다.
4. 투명 PNG의 실제 알파와 가장자리, 레이어별 크기·피벗·안전 영역을 검사한다. 기존 런타임 파일은 합격 전 덮어쓰지 않는다. 새 후보는 버전 폴더에 저장한다.
5. 화면별 최종 판정은 `docs/art/QUALITY-BAR.md`의 R1~R8을 사용한다. **10개 화면 각각** 평균 4.3 이상·전축 4 이상을 목표로 하고, 3뷰포트 오버플로/가림/글자 잘림, 실제 플레이/저장 회귀를 확인한다. 자동 QA 통과는 이 판정을 대체하지 않는다.
6. 코드 연결이 필요한 단계에서는 `AGENTS.md`의 9축 영향도 분석과 `docs/ANTIGRAVITY-LOOP.md`의 브랜치/PR 규칙을 따른다. 사용자 요청 범위에서는 아트 제작을 우선하고, 제미나이의 세부 UI 조정을 덮어쓰지 않는다.
