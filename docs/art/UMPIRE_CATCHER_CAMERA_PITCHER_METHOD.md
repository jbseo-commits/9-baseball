# 포수캠·심판캠 기반 투수 에셋 제작법

## 목표와 적용 범위

사용자가 새 투수를 요청하면 실제 포수 뒤·심판 시점의 투구 영상을 **동작과 카메라 자료**로 분석하고, 9ZONE의 홈플레이트 뒤 시점에 맞는 투수 키포즈와 애니메이션을 만든다. 새 투수는 등급에 관계없이 명백한 성인(25세 이상) 여성으로, 미형의 성적 매력이 도드라지는 비노골적 스포츠 디자인을 기본으로 한다. 자신감 있는 관능적 표정, 곡선이 드러나는 운동선수 체형, 몸에 맞는 크롭 저지·쇼츠 등을 활용하되 의상은 캐릭터에 맞게 설계한다. 프리미엄 9ZONE 픽셀 아트 품질을 유지하고 선수의 얼굴·유니폼을 베끼지 않는다. 기존 캐릭터는 별도 요청 없이는 재설계하지 않는다.

## 채팅 우선 제작·승인 게이트 (2026-10)

[`PITCHER_CHAT_FIRST_CACHE_WORKFLOW.md`](PITCHER_CHAT_FIRST_CACHE_WORKFLOW.md)를 먼저 적용한다. 기존 12포즈, 120프레임, 60fps와 실제 관절 움직임 검수 조건은 유지한다. 단, 신규 캐릭터 원화 후보 제작 전에 새 영상 검색을 강제하지 않는다. 검증된 영상 **분석 기록**을 캐시에서 사용하고, 새로운 메커닉·관점 등 결손이 있을 때만 신규 영상을 조사한다. 사용자에게 원화와 모션을 각각 승인받기 전에는 전체 아틀라스를 빌드하거나 프로덕션에 연결하지 않는다. 아래의 매 실행 신규 영상·미사용 영상 조건은 **새로운 영상 조사가 실제 필요해 수행되는 경우**에 적용한다. 기록되지 않은 시청과 관찰을 주장하지 않는다.

## 카메라와 캐릭터 계약

- 투수는 홈플레이트 뒤 카메라를 향해 거의 정면으로 보인다. 실게임 투수는 마운드에 발을 붙이고 화면의 기존 투수 기준점과 9존 UI를 침범하지 않는다.
- 오른손 투수라면 **오른손에 공, 왼손에 글러브**를 모든 프레임에서 유지한다. 공은 릴리스 직전까지 한 개만 보이고, 릴리스 후 손에서 사라진다.
- 얼굴·모자·헤어·유니폼·신발의 캐릭터별 특징을 키포즈마다 고정한다. 엘리트·보스의 매력은 표정, 실루엣, 몸의 회전, 의상과 광원으로 높이되 투구 동작과 장비 가독성을 해치지 않는다.
- 앞발 착지점, 축발 위치, 허리와 어깨 중심, 공의 위치를 각 키포즈에서 표시한다. 포즈 사이를 단순히 확대·이동하는 것만으로 완성 모션이라고 부르지 않는다.
- 새 캐릭터의 전신 세로형 원화에서 핵심 투구 키포즈 6개와 그 사이를 잇는 연결 포즈 6개를 설계하고, 각각 개별 투명 PNG로 보존한다. 게임용 아틀라스는 기존 `256×256` 셀, `10×12`, `120`프레임, `60fps` 계약에 맞춘다. 공용 빌더가 12개 포즈를 고정·회전·이동으로만 처리한다면 이를 자동 사지 트윈으로 간주하지 않는다. 실제 부드러운 관절 전환을 위해 중간 포즈를 직접 다시 그린다. 포즈 사이 실제 관절 움직임을 확인하기 전에는 120프레임 결과를 완성 애니메이션으로 표시하지 않는다.

## 제작·검수 순서

1. 캐릭터 원형과 현행 아틀라스를 비교해 중복 포즈를 피한다. 포수캠은 투수의 동작·축을, 심판캠은 화면 전체 구도와 공의 경로를 우선 참고한다.
2. 각 단계의 실루엣을 먼저 정하고, 체중 이동과 손잡이를 표시한 뒤 캐릭터별 키포즈를 만든다.
3. 원화의 전신·손·발·공·글러브·헤어가 잘리지 않았는지 확인하고 **실제 알파 채널**을 검사한다. 배경 그라데이션이 남은 이미지는 투명 게임 에셋으로 채택하지 않는다.
4. 공과 손의 연속성, 얼굴 방향, 발 접지, 팔·다리 개수, 복장 연속성을 프레임별로 검사한다. 최소 `set → leg-lift → foot-plant → release → follow-through`를 256px와 실게임 크기에서 반복 재생한다.
5. 모바일 세로·가로·PC 화면에서 마운드 접지, 얼굴 판독, UI 겹침, 타자와의 원근 비율을 확인한다. 기존 포즈와 나란히 놓고 블라인드 품질 평가를 거친다.
6. 게임 연결까지 승인된 작업에서만 검수 통과 뒤 런타임 매핑을 바꾸고, 투구 결과와 화면 전환까지 회귀 검증한다. 에셋 제작만 요청받았다면 검토 가능한 후보와 PR을 완성한다. 미통과 이미지는 후보 폴더에 두고 현행 에셋을 보존한다.

## 새 투수 실행 기본 경로와 빌드

별도 지정이 없으면 현재 로스터와 겹치지 않는 slug와 이름, 서로 다른 얼굴·헤어·팔레트·실루엣·투구폼을 설계한다. 기본은 성인 여성 우완 투수이며 캐릭터별 나이를 25세 이상으로 기록한다. 이미지 제작은 사용 가능한 이미지 생성 도구로 진행하고, 동일 캐릭터의 내부 검수 통과 원화를 후속 포즈의 참조로 유지한다.

- 실행 폴더: `assets/pitcher-study-<slug>/`. 기존 실행을 덮어쓰지 않는다. 이름 충돌 시 새 slug 또는 실행 접미사를 사용한다.
- `source/<slug>-portrait.png`: 투명 전신 원화. `source/<slug>-keys.png`, `source/<slug>-bridges.png`: 각각 1536×1024의 3×2 시트이며 포즈별 개별 PNG도 보존한다.
- 빌드: [`scripts/build-tide-vesper.py`](../../scripts/build-tide-vesper.py)를 시작점으로 `scripts/build-<slug>.py`를 만들고 ASSET·CHARACTER·포즈 타임라인을 실제 원화에 맞춘다. 공용 [`build-pitcher-roster-sd.py`](../../scripts/build-pitcher-roster-sd.py)의 추출·아틀라스 패킹 계약을 재사용하되, 전체 이미지 이동·회전은 팔다리 연결 포즈를 대체하지 않는다. 현재 포수 시점 연결 예시는 릴리스 76프레임이며 실제 게임 연결 시 손의 공 분리와 런타임 공 출발 시점을 함께 맞춘다.
- 산출물: `atlases/<slug>-pitch-120-atlas.png`, `<slug>-manifest.json`, `README.md`, `previews/<slug>-poses.png`, 재생 가능한 모션 프리뷰. 60fps 아틀라스와 GIF 프리뷰의 재생 속도를 혼동하지 않는다.
- 검수: 실제 알파·전신 여백·좌우 손잡이·발 접지·공 분리·얼굴/의상 일관성과 관절 전환을 256px 및 실게임 크기에서 확인한다. 결함이 있으면 새 연결 포즈를 제작하고 다시 빌드한다. 현재 후보·통과·차단 상태를 파일에 적고 후보 원화/프리뷰를 사용자에게 제시한다.

## 매 실행 기록과 범위

각 새 투수 제작 실행은 실행별 manifest/README와 reference log 갱신을 함께 남긴다. 기록에는 실제 검색 시각, 검색한 영상 후보와 URL, 채택 여부 및 상태, 정규화한 클립 식별자와 알려진 별칭, 실제 재생/관찰 여부, 키포즈별 영상 타임스탬프와 관찰 메모, `adult_age`(25 이상), 캐릭터 slug, 원화·포즈·아틀라스·빌드 스크립트 경로, 검증 결과와 영상 사용 이력을 포함한다. 검색·재생하지 않은 영상에 현재 관찰을 덧붙이거나 모르는 ID를 추정하지 않는다. 과거 출처는 이력/비교용으로만 남기며, 새 실행이 채택한 모든 참조는 다음 실행의 새 출처 선택에서 제외한다.

이 파이프라인은 검토 가능한 아트 에셋 후보를 만든다. 투수의 게임 로스터 연결, HP·밸런스, 런타임 로직 변경, main 반영이나 배포는 별도 범위와 승인·검수 절차를 따른다.
