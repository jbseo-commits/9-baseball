# 포수캠·심판캠 기반 투수 에셋 제작법

## 목표와 적용 범위

실제 포수 뒤·심판 시점의 투구 영상을 **동작과 카메라 자료**로 분석하고, 9ZONE의 홈플레이트 뒤 시점에 맞는 투수 키포즈와 애니메이션을 만든다. 선수의 얼굴·유니폼을 베끼지 않고 게임의 기존 캐릭터 정체성을 유지한다. 일반 투수는 기존 디자인을 유지하고, 엘리트·보스의 더 도발적이고 화려한 디자인은 캐릭터별 원형을 기준으로 별도 제작한다.

## 참고 영상과 증거 수준

1. [MLB: 포수 뒤에서 본 Dylan Cease 투구](https://www.mlb.com/video/behind-the-plate-view-of-cease) — 포수 뒤에서 마운드까지의 축, 투수 크기, 릴리스 방향 참고.
2. [MLB: Dodgers–Mets 심판캠 모음](https://www.mlb.com/video/best-of-ump-cam-from-dodgers-vs-mets) — 홈플레이트 뒤의 전경 타자, 중앙 투수, 공의 접근 방향 참고.

공식 페이지가 영상의 시점과 길이를 확인해 준다. 개별 프레임의 정확한 시간이나 관절 좌표는 이 문서에서 측정했다고 주장하지 않는다. 실제 제작 시 원본 영상을 열어 준비·다리 들기·착지·팔 가속·릴리스·팔로스루 프레임을 직접 표시하고 캡처 시간과 관찰을 아래 표에 남긴다. 영상 캡처 자체는 저장소에 올리지 않고, 출처 URL과 관찰만 기록한다.

| 단계 | 관찰할 것 | 게임 키포즈 |
| --- | --- | --- |
| 준비 | 양발 간격, 글러브 높이, 얼굴 방향 | `set` |
| 코일 | 축발의 위치, 골반 회전, 앞무릎 상승 | `coil`, `leg-lift` |
| 디딤 | 앞발 착지 위치, 글러브 팔 분리, 공 든 손의 연속성 | `stride`, `foot-plant` |
| 가속 | 어깨·팔꿈치·손의 순서, 뒤발 밀어내기 | `late-cocking`, `arm-whip` |
| 릴리스 | 공이 손에서 분리되는 순간과 화면 방향 | `release` |
| 회복 | 체중이 앞발로 넘어가고 뒷다리가 따라오는 경로 | `follow-through`, `recover` |

## 카메라와 캐릭터 계약

- 투수는 홈플레이트 뒤 카메라를 향해 거의 정면으로 보인다. 실게임 투수는 마운드에 발을 붙이고 화면의 기존 투수 기준점과 9존 UI를 침범하지 않는다.
- 오른손 투수라면 **오른손에 공, 왼손에 글러브**를 모든 프레임에서 유지한다. 공은 릴리스 직전까지 한 개만 보이고, 릴리스 후 손에서 사라진다.
- 얼굴·모자·헤어·유니폼·신발의 캐릭터별 특징을 키포즈마다 고정한다. 엘리트·보스의 매력은 표정, 실루엣, 몸의 회전, 의상과 광원으로 높이되 투구 동작과 장비 가독성을 해치지 않는다.
- 앞발 착지점, 축발 위치, 허리와 어깨 중심, 공의 위치를 각 키포즈에서 표시한다. 포즈 사이를 단순히 확대·이동하는 것만으로 완성 모션이라고 부르지 않는다.
- 원화는 개별 투명 PNG로 보존한다. 게임용 아틀라스는 기존 `256×256` 셀, `10×12`, `120`프레임, `60fps` 계약에 맞춘다. 포즈 사이 실제 관절 움직임을 확인하기 전에는 120프레임 결과를 완성 애니메이션으로 표시하지 않는다.

## 제작·검수 순서

1. 캐릭터 원형과 현행 아틀라스를 비교해 중복 포즈를 피한다. 포수캠은 투수의 동작·축을, 심판캠은 화면 전체 구도와 공의 경로를 우선 참고한다.
2. 각 단계의 실루엣을 먼저 정하고, 체중 이동과 손잡이를 표시한 뒤 캐릭터별 키포즈를 만든다.
3. 원화의 전신·손·발·공·글러브·헤어가 잘리지 않았는지 확인하고 **실제 알파 채널**을 검사한다. 배경 그라데이션이 남은 이미지는 투명 게임 에셋으로 채택하지 않는다.
4. 공과 손의 연속성, 얼굴 방향, 발 접지, 팔·다리 개수, 복장 연속성을 프레임별로 검사한다. 최소 `set → leg-lift → foot-plant → release → follow-through`를 256px와 실게임 크기에서 반복 재생한다.
5. 모바일 세로·가로·PC 화면에서 마운드 접지, 얼굴 판독, UI 겹침, 타자와의 원근 비율을 확인한다. 기존 포즈와 나란히 놓고 블라인드 품질 평가를 거친다.
6. 검수 통과 뒤에만 런타임 매핑을 바꾸고, 투구 결과와 화면 전환까지 회귀 검증한다. 미통과 이미지는 후보 폴더에 두고 현행 에셋을 보존한다.

## 이번 변경의 영향도 분석

이 문서와 후보 PNG만 추가하는 단계다. 런타임 연결은 별도 검수 후 진행한다.

| 축 | 판단 | 대응 |
| --- | --- | --- |
| UI·레이아웃 | 영향 없음 | 현재 화면 코드 미변경 |
| 입력·제스처 | 영향 없음 | 이벤트 미변경 |
| 게임 로직·밸런스 | 영향 없음 | 투구 수치 미변경 |
| 저장·불러오기 | 영향 없음 | 스키마 미변경 |
| 모바일 뷰포트 | 확인 필요 | 런타임 연결 전 세로·가로 실게임 크기 검사 |
| 스크롤·오버플로 | 영향 없음 | CSS 미변경 |
| 기존 사용자 플로우 | 영향 없음 | 후보 원화는 게임에서 미사용 |
| 테스트·회귀 | 확인 필요 | 알파·치수·손잡이 확인, 연결 시 재생·회귀 검사 |
| 빌드·배포 | 영향 없음 | import·번들 미변경 |
